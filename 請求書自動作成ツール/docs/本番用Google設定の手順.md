# 本番用 Google 設定の手順

本番用の Google Cloud（ログインの受付窓口）は **開発者のアカウントで先に作っておき**、依頼主は当日 **Google でログインするだけ** で使い始められるようにする（2026-11-27 決定）。
納品のときに、Google Cloud の持ち主（オーナー）を依頼主にも追加して引き継ぐ。

## 0. しくみ（先に読む）

- **データは依頼主の Google ドライブ**に入る。開発者のアカウントから依頼主の名簿は見えない。
  Google Cloud は「このアプリでログインしてよいか」を受け付ける窓口を作るだけ。
- アプリの許可は「**このアプリが作ったファイルだけ**読み書きできる」（`drive.file`）。
  「このアプリ」は **クライアントID ごと**に区別されるので、**開発用のクライアントIDで作ったスプレッドシートは本番からは開けない**。
  → 本番のデータは、必ず**本番のクライアントIDで**新しく作る。
- 本番の Google Cloud は、あとで**作り直さずに**依頼主へ引き継ぐ（手順5）。クライアントIDが変わらないので、スプレッドシートもそのまま使える。
- 開発用（「利用記録・請求書」）と本番用は**別のプロジェクト**にする。テストユーザーや、引き継ぐ範囲がはっきり分かれる。

## 1. 事前準備（開発者が1人でやる・約20分）

### 1-1. 依頼主に聞いておくこと
- [ ] ログインに使う **Google アカウントのメールアドレス**（Gmail など）
- [ ] 当日、そのアカウントの**パスワード**と、2段階認証用の**スマホ**を持ってきてもらう
- [ ] （あれば）負担割合が **2割・3割の人の一覧**（当日その場で直すなら）

### 1-2. 本番用のプロジェクトを作る
1. https://console.cloud.google.com/ を開き、**開発者のアカウント**でログイン。
2. 上の「プロジェクトを選択」→「新しいプロジェクト」。名前：**`Attendance Invoice Production`**（プロジェクト名は英数字・スペース・ハイフンなどしか使えないため英語）。「作成」。
3. 上の欄が「Attendance Invoice Production」に切り替わったことを確認（**開発用と取り違えない**）。

### 1-3. Google Sheets API を有効にする
1. 左のメニュー「API とサービス」→「ライブラリ」。
2. 「Google Sheets API」を検索して開き、「**有効にする**」（Drive API は使っていないので不要）。

### 1-4. Google Auth Platform（ログイン画面の設定）
1. 左のメニュー「Google Auth Platform」（または「OAuth 同意画面」）→「開始」。
2. **アプリ情報**：アプリ名「利用記録・請求書」、ユーザーサポートメールは開発者のメールアドレス。
3. **対象**：「**外部**」。
4. **連絡先情報**：開発者のメールアドレス。同意して「作成」。
5. 「対象」→「テストユーザー」→「ユーザーを追加」で **依頼主のメールアドレスだけ** を追加。
   → ログインできるのは依頼主だけ（2026-11-27 決定：アプリを使うのは依頼主だけ）。
6. 「公開ステータス」は **「テスト」のまま**（「アプリを公開」は押さない）。

### 1-5. クライアントIDを作る
1. 「Google Auth Platform」→「クライアント」→「クライアントを作成」。
2. 種類：**ウェブ アプリケーション**。名前：「利用記録・請求書（本番）」。
3. 「承認済みの JavaScript 生成元」に **`http://localhost:3000`** を追加。
   （公開したら公開先の `https://〜` を**追加**する。追加してもスプレッドシートはそのまま使える）
4. 「承認済みのリダイレクト URI」は空のまま。
5. 「作成」→ **クライアントID**（`〜.apps.googleusercontent.com`）を控える。クライアントシークレットは使わない。

### 1-6. 本番の設定ファイルを用意しておく
1. 今の `.env.local`（開発用）をコピーして **`.env.local.開発用`** という名前で残す。
2. 同じようにコピーして **`.env.local.本番`** を作り、中のクライアントIDを本番のものに書き換える：
   ```
   NEXT_PUBLIC_GOOGLE_CLIENT_ID=（1-5で控えた本番のクライアントID）
   NEXT_PUBLIC_DATA_BACKEND=sheets
   ```
   （どちらのファイルも Git には入らない。クライアントIDは秘密の鍵ではないが、名簿と同じく外に出さない）
3. 自分のアカウントで試す場合は、テストユーザーに自分も一時的に追加し、試した後に**削除**する（本番の窓口で作ったテスト用スプレッドシートは自分のドライブから消す）。

## 2. 当日（依頼主と会う日・約10〜15分）

当日は時間ごとの台本 [当日の進行表.md](当日の進行表.md) を見ながら進める。

開発者のPCで行う。名簿ファイル（`個人情報/会員登録用_利用者名簿_2026-11-27.json`）は開発者のPCにあるので、持ち運ばない。

### 2-1. アプリを本番の設定で起動する（依頼主が来る前に）
1. `.env.local.本番` の中身を `.env.local` にコピーする。
2. アプリを起動し直す（黒い画面を閉じて `起動.bat`）。

### 2-2. 依頼主にログインしてもらう
1. Chrome の **ゲストウィンドウ** で http://localhost:3000 を開く（閉じればログイン情報がPCに残らない）。
2. 「Google でログイン」→ 依頼主のアカウントでログイン（2段階認証のスマホ確認があればここで）。
   - 「このアプリは Google で確認されていません」→「詳細」→「利用記録・請求書（安全ではないページ）に移動」。テスト中のアプリでは必ず出る表示で、問題ないことを伝える。
   - 許可の画面（「このアプリが作ったファイルだけ」）で「続行」。
3. 「はじめて使う：新しく作る」を押す。依頼主のマイドライブにスプレッドシートができる。
4. **スプレッドシートの URL を控える**（公開後に「URLで開く」で使う）。

### 2-3. 名簿を読み込む（開発者が操作）
1. 「会員管理」→ 一番下「データのバックアップ」→「**読み込み**」。
2. `個人情報/会員登録用_利用者名簿_2026-11-27.json` を選ぶ →「置き換えます」で OK。
3. 一緒に確認：会員一覧に **34名（M0001〜M0034）**。依頼主のドライブのスプレッドシートの「会員」シートに34行（中身は手で編集しない）。

### 2-4. 時間があれば
- 使い方の説明（出欠の付け方・保存・請求書の出し方）：15〜20分
- 依頼主に確認・修正してもらうこと（あとで依頼主が1人でやってもよい）：
  - [ ] **負担割合**：今は全員「1割」（仮）。「会員管理」→「編集」→「負担割合の変更（何月分から）」
  - [ ] **氏名の表記**：紙から読み取ったときに怪しかった4名（登録用ファイル作成時の記録を参照）
  - [ ] **利用曜日・時間帯（午前／午後）**が紙の名簿と合っているか
  - [ ] 利用開始日は全員 2026-11-01。これでよいか

### 2-5. 終わったら
1. ゲストウィンドウを閉じる。
2. `.env.local.開発用` の中身を `.env.local` に戻し、アプリを起動し直す（開発中に本番の窓口を使わないため）。
3. 控えたスプレッドシートの URL は `個人情報/` フォルダなど Git に入らない場所へ。
4. 開発者のPCにある名簿ファイルの扱い（残すか消すか）を依頼主と決める。

## 3. 公開するとき（後日）
- `src/config.ts` の `OFFICE` を本当の事業所情報（名前・住所・電話）にし、`isDemo` を `false` にする（画面の「試作版」、タブの「（試作版）」、請求書の「デモ用・架空」が消える）。正式な請求書ひな形の反映と同時に行う。
- 公開先（Cloudflare Pages）の `https://〜` を、1-5 の「承認済みの JavaScript 生成元」に追加。
- 公開先の環境変数に、本番の `NEXT_PUBLIC_GOOGLE_CLIENT_ID` と `NEXT_PUBLIC_DATA_BACKEND=sheets` を入れる。
- 依頼主のPCで公開先を開き、ログイン →「前に作ったものを使う：URLで開く」に 2-2 で控えた URL を入れる。

## 4. 引き継ぐまでの注意
- 本番の窓口は開発者のアカウントにある。**このプロジェクトを削除したり、開発者のアカウントを消したりすると、依頼主がアプリにログインできなくなる**（データはドライブに残り、スプレッドシートとしては開ける）。
- テストユーザーは依頼主だけにしておく。

## 5. 納品のときの引き継ぎ
1. Google Cloud（本番のプロジェクト `Attendance Invoice Production`）→「IAM と管理」→「IAM」→「アクセスを許可」。
2. 依頼主のメールアドレスを入れ、ロール「**オーナー**」→「保存」。依頼主に招待メールが届くので「承諾」してもらう。
3. Google Auth Platform のユーザーサポートメール・連絡先を、依頼主のメールアドレスに変える。
4. 開発者が保守を続けるなら開発者は「編集者」として残る。保守しないなら、開発者を IAM から外す。
5. 引き継ぎの方法と時期を、契約・検収・保守の取り決めに書いておく。

## 困ったとき
| 症状 | 対処 |
|---|---|
| 「アクセスをブロック：〜はテスト中です」 | 1-4 の 5 で、そのアカウントがテストユーザーに入っているか |
| 「redirect_uri_mismatch」「origin が許可されていません」 | 1-5 の 3 に、開いている住所（`http://localhost:3000` など）が入っているか。番号（3000 / 3001）も一致が必要 |
| スプレッドシートの URL を入れても開けない | 別のクライアントID（開発用など）で作ったファイル。`.env.local` が本番になっているか |
| 約1時間で「接続が切れました」が出る | Google の許可の期限。そのまま「保存」を押せば自動でつなぎ直す（「再接続」を押してもよい。入力中の内容は消えない） |
