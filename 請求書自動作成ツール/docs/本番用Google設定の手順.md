# 本番用 Google 設定の手順（依頼主のアカウントで作る）

依頼主と一緒に作業する日に使う手順書です。所要時間は **約1時間**（説明・確認を含む）。

## 0. なぜ作り直すのか（先に読む）

- 今の Google Cloud（開発用「利用記録・請求書」）は**開発者本人のアカウント**で作ったもので、テスト用です。
- アプリの許可は「**このアプリが作ったファイルだけ**読み書きできる」（`drive.file`）です。
  「このアプリ」は **クライアントID ごと**に区別されるため、開発用のクライアントIDで作ったスプレッドシートは、本番用のクライアントIDからは開けません。
- そのため、順番は必ず **① 本番用 Google Cloud を作る → ② そのクライアントIDでスプレッドシートを新しく作る → ③ 名簿を読み込む** です。
  開発用の設定のまま名簿を読み込んでも、本番には引き継げません。

## 1. 日程を決める前に、依頼主に確認すること

| 確認すること | 理由 |
|---|---|
| データを置く Google アカウント（Gmail か、事業所の Google Workspace か） | 手順 3-3 の「対象」の選び方が変わる |
| そのアカウントのパスワードと、2段階認証のスマホ（当日手元にあるか） | ログインに必要 |
| 当日使うパソコン（依頼主のPCか、開発者のPCか） | 下の「2. 当日の進め方」を参照 |
| 開発者を Google Cloud の「編集者」に追加してよいか | 追加すると、後の設定変更（公開先の追加など）を開発者側でできる |

## 2. 当日の進め方（おすすめ）

- **Google Cloud の設定（手順3）**：依頼主が自分のアカウントでログインし、開発者が横で画面を案内する。
- **名簿の読み込み（手順4）**：アプリはまだ公開前なので、**開発者のPC**（アプリが動いているPC）で行う。
  - 依頼主にログインしてもらうときは、開発者の普段のブラウザを使わず、**Chrome の「ゲスト」ウィンドウ**（または新しいプロフィール）を使う。終わったら閉じれば、依頼主のログイン情報はPCに残らない。
  - 名簿ファイル（`個人情報/会員登録用_利用者名簿_2026-11-27.json`）は開発者のPCにあるので、ファイルを持ち運ぶ必要がない。
  - ※ どうしても依頼主のPCで行う場合は、名簿ファイルをメールやチャットで送らず、USBメモリで渡し、作業後に依頼主のPCから消す。

## 3. 本番用 Google Cloud を作る（依頼主のアカウント）

### 3-1. プロジェクトを作る
1. https://console.cloud.google.com/ を開き、**依頼主のアカウント**でログインする（右上の丸いアイコンで、依頼主のアカウントになっているか確認）。
2. 初めての場合は利用規約に同意する（**お支払い情報の登録は不要**）。
3. 上の「プロジェクトを選択」→「新しいプロジェクト」。名前は **「利用記録・請求書」**。「作成」。
4. 作成後、上の欄が「利用記録・請求書」になっていることを確認。

### 3-2. Google Sheets API を有効にする
1. 左のメニュー「API とサービス」→「ライブラリ」。
2. 「Google Sheets API」を検索して開き、「**有効にする**」。
   （Drive API は使っていないので不要）

### 3-3. Google Auth Platform（ログイン画面の設定）
1. 左のメニュー「Google Auth Platform」（または「OAuth 同意画面」）→「開始」。
2. **アプリ情報**：アプリ名「利用記録・請求書」、ユーザーサポートメールは依頼主のメールアドレス。
3. **対象**：
   - Gmail（個人アカウント）の場合 → **「外部」**
   - 事業所の Google Workspace の場合 → **「内部」**（事業所のアカウントだけが使える。テストユーザーの登録は不要）
4. **連絡先情報**：依頼主のメールアドレス。
5. 同意して「作成」。
6. 「外部」を選んだ場合のみ：「対象」→「テストユーザー」→「ユーザーを追加」で **依頼主のメールアドレスだけ** を追加。
   → ログインできるのは依頼主だけになる（2026-11-27 決定：アプリを使うのは依頼主だけ）。
   - 「公開ステータス」は **「テスト」のまま** にする（「アプリを公開」は押さない）。

### 3-4. クライアントIDを作る
1. 「Google Auth Platform」→「クライアント」→「クライアントを作成」。
2. アプリケーションの種類：**ウェブ アプリケーション**。名前：「利用記録・請求書（本番）」。
3. 「承認済みの JavaScript 生成元」に **`http://localhost:3000`** を追加。
   （公開したら、公開先の住所 `https://〜` をここに**追加**する。後から追加しても、作ったスプレッドシートはそのまま使える）
4. 「承認済みのリダイレクト URI」は空のままでよい。
5. 「作成」→ 表示された **クライアントID**（`〜.apps.googleusercontent.com`）を控える。
   - クライアントシークレットは使わない（控えなくてよい）。

### 3-5. （確認できた場合）開発者を編集者に追加
1. 左のメニュー「IAM と管理」→「IAM」→「アクセスを許可」。
2. 新しいプリンシパルに開発者のメールアドレス、ロールは「**編集者**」。「保存」。

## 4. アプリを本番の設定に切り替えて、名簿を読み込む（開発者のPC）

### 4-1. 開発用の設定を控えてから書き換える
1. `.env.local` をコピーして `.env.local.開発用` という名前で残す（元に戻すとき用）。
2. `.env.local` を次のようにする：
   ```
   NEXT_PUBLIC_GOOGLE_CLIENT_ID=（手順3-4で控えた本番のクライアントID）
   NEXT_PUBLIC_DATA_BACKEND=sheets
   ```
3. アプリを起動し直す（黒い画面を閉じて `起動.bat`）。

### 4-2. ログインしてスプレッドシートを作る
1. **ゲストウィンドウ**で http://localhost:3000 を開く。
2. 「Google でログイン」→ 依頼主のアカウントを選ぶ。
   - 「このアプリは Google で確認されていません」と出たら、「詳細」→「利用記録・請求書（安全ではないページ）に移動」。テスト中のアプリでは必ず出る表示で、問題ない。
   - 許可の画面で「このアプリが作ったファイルだけ」の許可を「続行」。
3. 「はじめて使う：新しく作る」を押す。依頼主のマイドライブにスプレッドシートができる。
4. **スプレッドシートの URL を控える**（公開後や別のPCで使うとき、「URLで開く」に入れる）。

### 4-3. 名簿を読み込む
1. 「会員管理」→ 一番下「データのバックアップ」→「**読み込み**」。
2. `個人情報/会員登録用_利用者名簿_2026-11-27.json` を選ぶ →「置き換えます」の確認で OK。
3. 会員一覧に **34名（M0001〜M0034）** が出ることを確認。
4. 依頼主のドライブでスプレッドシートを開き、「会員」シートに34行あることを確認（中身は手で編集しない）。

### 4-4. 依頼主に確認・修正してもらうこと
- [ ] **負担割合**：今は全員「1割」（仮）。「会員管理」→「編集」→「負担割合の変更（何月分から）」で直す。
- [ ] **氏名の表記**：紙から読み取ったときに怪しかった4名（登録用ファイル作成時の記録を参照）。
- [ ] **利用曜日・時間帯（午前／午後）**が紙の名簿と合っているか。
- [ ] 利用開始日は全員 2026-11-01 で登録している。これでよいか。

## 5. 終わったあと

1. ゲストウィンドウを閉じる（依頼主のログイン情報がPCに残らない）。
2. 開発を続けるときは `.env.local` を `.env.local.開発用` の内容に戻し、アプリを起動し直す。
   - 本番のクライアントIDのままにしておくと、開発中の操作が依頼主のデータに触れてしまう恐れがある。
3. 控えたもの（クライアントID・スプレッドシートのURL）は、名簿と同じく `個人情報/` フォルダなど Git に入らない場所に保存する。
4. 開発者のPCにある名簿ファイルの扱い（残すか消すか）を依頼主と決める。

## 6. 公開するときに追加でやること（後日）

- 公開先（Cloudflare Pages）の住所 `https://〜` を、手順3-4の「承認済みの JavaScript 生成元」に追加する。
- 公開先のビルド設定（環境変数）に、本番の `NEXT_PUBLIC_GOOGLE_CLIENT_ID` と `NEXT_PUBLIC_DATA_BACKEND=sheets` を入れる。
- 依頼主のPCで公開先を開き、ログイン →「前に作ったものを使う：URLで開く」に、手順4-2で控えたスプレッドシートの URL を入れる。

## 困ったとき

| 症状 | 対処 |
|---|---|
| 「アクセスをブロック：〜はテスト中です」 | 手順3-3の6で、そのアカウントがテストユーザーに入っているか確認 |
| 「redirect_uri_mismatch」「origin が許可されていません」 | 手順3-4の3に、開いている住所（`http://localhost:3000` など）が入っているか。番号（3000 / 3001）も一致が必要 |
| スプレッドシートの URL を入れても開けない | 別のクライアントID（開発用など）で作ったファイル。`.env.local` のクライアントIDを確認 |
| 約1時間で「再接続」が出る | Google の許可の期限。「再接続」を押せばよい（入力中の内容は消えない） |
