# Googleスプレッドシート・ドライブ連携の準備

> **注意：これは初期の案です。** 実際のアプリはサービスアカウントではなく、ブラウザで Google にログインする方式（`drive.file`）で作りました。本番の設定は [本番用Google設定の手順.md](本番用Google設定の手順.md) を見てください。

試作版はブラウザ内に保存しています。次の段階で、Googleスプレッドシートに保存し、請求書をGoogleドライブに保存する想定です。

## 1. 依頼主に確認すること
- 月初の自動作成の時刻（例：毎月1日 6:00 に前月分）
- 入力の締切（例：毎月末日まで。締切後の修正を許すか）
- 修正後の再作成方法（作り直した請求書で上書き／版を残す）
- 正式な請求書の書式（ひな形の入手、印鑑・振込先・但し書きなどの項目）
- 端末の運用（共用1台のみか、タブレット等も使うか）、職員ごとのログインが必要か
- データを置くGoogleアカウント（事業所のGoogle Workspace か、個人アカウントか）

## 2. Google側で必要な準備
1. **Google Cloud のプロジェクト**を作成し、**Google Sheets API** と **Google Drive API** を有効にする
2. 認証方式を決める
   - おすすめ：**サービスアカウント**（サーバーから決まったスプレッドシートを読み書き。職員がGoogleにログインする必要がない）
   - スプレッドシートと保存先フォルダを、サービスアカウントのメールアドレスに「編集者」で共有する
3. 保存用の**スプレッドシート**と、請求書用の**ドライブのフォルダ**を作り、それぞれのIDを控える
4. 鍵（サービスアカウントのJSON鍵など）は**ソースコードに書かず**、環境変数で渡す（`.env.local` または公開先の環境変数設定。`.env.example` を参照）

## 3. スプレッドシートのシート構成（案）
| シート | 列 |
|---|---|
| 会員 | 会員ID, 氏名, ふりがな, 退会日, 作成日時, 更新日時 |
| 利用曜日 | 会員ID, 開始日, 曜日（例：月,水） |
| 負担割合 | 会員ID, 適用開始月, 割合（1/2/3） |
| 出欠 | 日付, 会員ID, 状態（利用/欠席/未確認）, 追加フラグ, 保存日時, 保存した端末/職員 |
| 単価 | 適用開始月, 1割の単価, 2割の単価, 3割の単価 |
| 請求書 | 対象月, 会員ID, 回数, 金額, 作成日時, ドライブのファイルID |

アプリ内のデータの形（`src/lib/types.ts`）と1対1で対応させています。

## 4. アプリ側の作業
1. `src/services/sheetsRepository.ts` を作り、`Repository`（`src/services/repository.ts`）と同じ関数を実装する
   - ブラウザから直接Googleにはつながず、Next.js のサーバー側（`src/app/api/...`）を経由する（鍵をブラウザに出さないため）
2. `getRepository()` で、環境変数 `NEXT_PUBLIC_DATA_BACKEND=sheets` のときに切り替える
3. 試作版のデータを移すときは、会員管理の「書き出し」で作ったJSONを読み込むスクリプトを用意する
4. 同時に2台で保存したときの扱い（後から保存した方を優先するか、確認を出すか）を決める
5. 月初の請求書作成：定期実行（例：Vercel Cron / Google Apps Script のトリガー）で、`summarizeMonth()`（`src/lib/billing.ts`）の結果からPDFを作り、ドライブに保存
6. 公開する場合は、ログイン（事業所の職員だけが使える仕組み）を必ず付ける

## 5. 本番前のチェック
- 実データを入れる前に、個人情報の取り扱い（保存先・閲覧できる人・バックアップ）を依頼主と確認
- `npm run check` と、架空データでの通し確認
