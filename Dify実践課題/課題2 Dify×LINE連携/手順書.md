# Dify × LINE 連携ボット 手順書

LINEで送ったメッセージに、Difyで新しく作ったAIボットが答える仕組みを作ります。

## 0. 全体の仕組み

```
LINEユーザー ─▶ LINE公式サーバー ─(Webhook)─▶ 中継プログラム(Vercel) ─▶ Dify
LINEユーザー ◀─ LINE公式サーバー ◀─(返信API)── 中継プログラム(Vercel) ◀─ Dify
```

| 用語 | 意味 |
|---|---|
| API | プログラム同士が会話するための窓口 |
| Webhook | 「何か起きたらこのURLに知らせて」という仕組み。LINEがメッセージ到着を中継プログラムに知らせる |
| APIキー／アクセストークン | 窓口を使うための合鍵。人に見せない |
| チャネルシークレット | LINEからの通知が本物か確かめる合言葉 |
| Vercel | プログラムをインターネット上に公開できるサービス（無料枠あり） |
| 環境変数 | 合鍵などをプログラム本体に書かずに、サーバー側に別保管する仕組み |

## ファイルの役割

| ファイル | 役割 |
|---|---|
| `api/webhook.js` | 玄関口。LINEからの通知を受け取り、署名を確認する |
| `api/_lib/handler.js` | 司令塔。友だち追加・質問・リセットなどを振り分ける |
| `api/_lib/dify.js` | Difyに質問して回答をもらう係。会話の続きも引き継ぐ |
| `api/_lib/line.js` | LINEに返信する係。「考え中…」表示もする |
| `test/bot.test.js` | 偽物のLINE・Difyで動作を確かめるテスト（`npm test`） |

## ステップ0：Difyでボットを新しく作る（ひだまり珈琲店）

### 0-1. ナレッジ（メニュー表）を作る
1. https://cloud.dify.ai → 上の「ナレッジ」→「ナレッジを作成」
2. 「テキストファイルからインポート」で `ナレッジ/ひだまり珈琲店_メニュー表.md` をアップロード →「次へ」
3. チャンク設定（資料をどう小分けにするか）
   - 方式：「汎用」
   - チャンク識別子（区切り文字）：`\n\n`（空行で区切る＝1品ずつ分かれる）
   - 最大チャンク長：500
   - 「プレビュー」を押し、1品ずつ分かれているか確認
4. インデックス方法：「高品質」（埋め込みモデルは OpenAI の `text-embedding-3-small` など）
5. 検索設定：「ハイブリッド検索」（意味の近さ＋キーワード一致の両方で探す）
6. 「保存して処理」→ 処理が終わるまで待つ
7. 左メニュー「検索テスト」で「甘くないおやつ」「小麦アレルギーでも食べられるケーキ」などを入れ、正しい段落が上位に出るか確認

### 0-2. チャットフローを作る
1. 上の「スタジオ」→「最初から作成」→「チャットフロー」、名前は「ひだまり珈琲店ボット」
2. 「開始」と「LLM」の間の線にある「＋」→「知識検索」を追加
3. 知識検索ブロック
   - クエリ変数：`sys.query`（お客さんの質問文）
   - ナレッジ：「＋」から 0-1 で作ったナレッジを選ぶ
   - 検索設定：Top K は 3〜4 くらい
4. 「LLM」ブロック
   - モデルを選ぶ（mini 系でOK）
   - 「コンテキスト」欄で、知識検索ブロックの `result` を選ぶ
   - 「メモリ」がオンになっていることを確認

### 0-3. 指示文を入れる
1. LLMブロックの「SYSTEM」欄に `プロンプト.md` の線から線までを貼り付ける
2. 「ここにコンテキストを入れる」の1行を消し、その位置で「{」（または「/」）を入力 →「コンテキスト」を選んで差し込む
3. 右上「プレビュー」で試す（下の確認質問を参照）
4. 右上「公開する」→「公開」

**確認質問の例**
| 質問 | 期待する答え |
|---|---|
| 甘くないおやつはありますか？ | 塩バタースコーン（380円）など |
| 小麦アレルギーでも食べられるケーキは？ | 米粉のシフォンケーキ＋同じ厨房である旨の注意 |
| カレーは夕方も食べられる？ | 11:00〜15:00限定、1日15食 |
| パフェはありますか？ | 用意がない旨＋近いスイーツの紹介（パフェを作り話しない） |
| 水曜日は開いてる？ | 定休日（指示文の基本情報から） |

## ステップ1：DifyのAPIキーを取る

1. https://cloud.dify.ai を開き、ステップ0で作ったアプリを開く
2. 右上「公開する」→「更新」を押して最新の状態を公開しておく
3. 左メニューの「APIアクセス」を開く
4. 右上「APIキー」→「新しいシークレットキーを作成」
5. 表示された `app-` で始まる文字列をメモ帳に控える（**DIFY_API_KEY**）

> 💡 Difyの「開始」ブロックに必須の入力欄を作っている場合は、API経由だとエラーになります。必須を外すか、`api/_lib/dify.js` の `inputs` に値を入れてください。

## ステップ2：LINE公式アカウントとMessaging APIチャネルを作る

1. https://developers.line.biz/console/ にLINEアカウントでログイン
2. 「プロバイダー」を作成（名前は自分の名前や屋号など何でもOK）
3. 「Messaging API」チャネルを作成
   - 現在は、LINE公式アカウントを作ってから Messaging API を有効化する流れになっています。画面の案内（「LINE公式アカウントを作成する」）に従ってください。
   - その後、LINE Official Account Manager の「設定」→「Messaging API」→「Messaging APIを利用する」で、ステップ2のプロバイダーを選びます。
4. LINE Developers に戻り、作ったチャネルを開く
5. 「チャネル基本設定」タブ →「チャネルシークレット」を控える（**LINE_CHANNEL_SECRET**）
6. 「Messaging API設定」タブ → 一番下「チャネルアクセストークン（長期）」→「発行」して控える（**LINE_CHANNEL_ACCESS_TOKEN**）

## ステップ3：LINE公式アカウントの自動応答をオフにする

LINE Official Account Manager →「設定」→「応答設定」

- 「チャット」：オフ
- 「あいさつメッセージ」：オフ（ボット側であいさつを返すため。二重になるのを防ぐ）
- 「Webhook」：オン
- 「応答メッセージ」：オフ（オンのままだと定型文が一緒に返ってしまう）

## ステップ4：Vercelに公開（デプロイ）する

1. https://vercel.com でアカウント作成（GitHubかGoogleで登録が簡単）
2. このフォルダでターミナルを開き、Vercelにログイン
   ```
   npx vercel login
   ```
3. 公開する（質問にはすべて Enter でOK）
   ```
   npx vercel deploy --prod
   ```
4. 合鍵3つを環境変数として登録（1つずつ実行し、値を貼り付ける。環境は Production を選ぶ）
   ```
   npx vercel env add LINE_CHANNEL_SECRET production
   npx vercel env add LINE_CHANNEL_ACCESS_TOKEN production
   npx vercel env add DIFY_API_KEY production
   ```
5. 環境変数を反映させるため、もう一度公開
   ```
   npx vercel deploy --prod
   ```
6. 表示されたURL（例：`https://dify-line-bot.vercel.app`）の末尾に `/api/webhook` を付けてブラウザで開き、「動いています 🟢」と出ればOK

> ⚠️ Vercelの「Deployment Protection（デプロイ保護）」が有効だと、LINEからのアクセスが弾かれます。本番URL（`〇〇.vercel.app`）は通常保護されませんが、「Webhookの検証」が失敗したら Vercel の Settings → Deployment Protection を確認してください。

## ステップ5：LINEにWebhook URLを登録する

1. LINE Developers →（チャネル）→「Messaging API設定」タブ
2. 「Webhook URL」に `https://（あなたのURL）/api/webhook` を入れて「更新」
3. 「検証」を押して「成功」と出ればOK
4. 「Webhookの利用」をオンにする

## ステップ6：友だち追加して試す

1. 「Messaging API設定」タブのQRコードをスマホのLINEで読み取って友だち追加
2. あいさつが届く → 「料金を教えて」などと送る → AIが答えれば完成 🎉
3. 「リセット」と送ると、会話の記憶がリセットされる

## うまく動かないとき

| 症状 | 確認すること |
|---|---|
| Webhookの「検証」が失敗 | URLの末尾が `/api/webhook` か／LINE_CHANNEL_SECRET が正しいか／再デプロイしたか |
| 検証は成功するが返事がない | Vercel のダッシュボード →（プロジェクト）→「Logs」でエラーを見る |
| 「ただいま回答できませんでした」と返る | DIFY_API_KEY が正しいか／Difyのアプリを「公開」したか |
| 定型文が一緒に返ってくる | ステップ3の「応答メッセージ」をオフに |
| ログに 401 / Unauthorized | アクセストークンを再発行して、環境変数を更新→再デプロイ |

## 発展案

- **ナレッジを育てる**：メニュー表に加えて「よくある質問」「イベント・臨時休業のお知らせ」もナレッジに入れると、答えられる範囲が広がります。メニューが変わったら、ナレッジのファイルを差し替えるだけでLINEの回答も変わります（プログラムの変更は不要）。
- **リッチメニュー**：LINE Official Account Manager でトーク画面下部にボタン（「料金」「場所」「体験予約」）を作り、押すと定型文が送られるようにすると、質問のハードルが下がります。プログラムの変更は不要です。
- **人間へのエスカレーション**：Difyで「予約」「ケガ」などの質問を分類し、回答の最後に「スタッフにおつなぎします」と返す。LINE Official Account Manager のチャットに切り替えて人が対応する運用ができます。
- **画像対応**：Difyの画像入力（Vision）対応モデルを使い、`api/_lib/handler.js` で画像メッセージも受け取れるように拡張できます（フォーム写真の読み取りなど）。
- **会話の記録・分析**：Difyの「ログ」画面に `line-` で始まるユーザー名で記録が残ります。よくある質問を見つけて、指示文やナレッジを改善しましょう。
- **グループトーク対応**：今はグループでも全発言に反応します。「@ボット名」を含むときだけ答えるようにすると、グループでも使いやすくなります。
