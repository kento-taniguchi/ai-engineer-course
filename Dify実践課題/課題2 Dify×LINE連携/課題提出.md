## B. 実装内容

### 使用技術

- **言語**：JavaScript（Node.js）
- **フレームワーク**：
  - Dify（クラウド版）チャットフロー・ナレッジ
  - Vercel Functions（サーバーレス関数）
- **データベース**：なし（会話の記憶はDifyの会話履歴を使った）
- **その他ツール**：
  - LINE Messaging API（Webhook・返信・考え中アニメーション）
  - Dify API（`/chat-messages`、`/conversations`）
  - OpenAI API（mini系のモデル、埋め込みモデル `text-embedding-3-small`）
  - Vercel（デプロイ先、環境変数の管理）
  - Node.js標準のテスト機能（`node --test`）
  - Claude Code（プログラムの作成・手順の解説のサポート）

### 実装した機能

1. LINEで送った質問に、DifyのAIが答えて返信する
2. メニュー・値段・アレルギーの質問は、ナレッジのメニュー表から関係する品を探して答える（知識検索）
3. 前の会話の続きとして答える（「それにおすすめの飲み物は？」が通じる）
4. 「リセット」と送ると、会話の記憶をリセットして新しい話題として始める
5. 友だち追加したときに、お店のあいさつを自動で送る
6. AIが回答を作っている間、トーク画面に「考え中…」のアニメーションを表示する
7. スタンプや画像には「文字のメッセージでご質問ください」と案内する
8. メニュー表にない品は作り話をせず、「ご用意がない」と伝えて近いメニューを紹介する
9. Vercelにデプロイし、LINEで友だち追加するだけで24時間使えるようにした

### 工夫したポイント

- **なりすまし対策（署名チェック）**：LINEから届いた通知が本物かを、チャネルシークレットを使った署名で確かめ、一致しないものは拒否（401）するようにした
- **APIキーの管理**：3つの合鍵（DifyのAPIキー、LINEのチャネルシークレット・アクセストークン）はプログラムに書かず、Vercelの環境変数に自分の手で直接登録した。チャットにも貼らなかった
- **データベースなしで会話を引き継ぐ**：Difyが「ユーザーごとの会話一覧」を返してくれるAPIを使い、毎回いちばん新しい会話IDを聞くことで、データベースを用意せずに会話の続きができるようにした
- **LINEを待たせない**：LINEには「受け取ったよ」とすぐ返事をして、AIの回答作りは裏側で続ける（`waitUntil`）ようにした
- **返信できないときの予備手段**：返信用の整理券（replyToken）が期限切れで使えなかったときは、プッシュ送信に切り替えて必ず届くようにした
- **LINEで読みやすくする**：AIが使いがちな「**」「#」などの記号を、指示文で禁止したうえで、プログラムでも取り除いた。長い回答は5000文字ごとに分けて送る
- **ナレッジを探しやすく作った**：メニュー表を「1品＝1段落」にして、どの段落にも分類・値段・特徴・アレルギーを全部書いた。切り分けたあとのかたまりだけを読んでも意味が分かるようにするため
- **指示文とナレッジの使い分け**：毎回使う短い情報（営業時間など）は指示文に、量が多く質問によって必要な部分が変わる情報（メニュー）はナレッジに入れた
- **アレルギーへの配慮**：アレルギーの質問には、必ず「同じ厨房で調理している」注意を添えるルールにした
- **本物につなぐ前にテスト**：偽物のLINE・Difyを用意したテストを7つ作り、署名チェック・返信・プッシュ送信への切り替え・リセットなどが正しく動くことを確認してからデプロイした
- **見せなくていいファイルは公開しない**：手順書・メニュー表・テストはVercelにアップロードしない設定にし、プログラム本体も外から読めない場所（`api/_lib`）に置いた

**遭遇したエラー①：ナレッジのアップロードに失敗した**

```
アップロードに失敗しました
```

Claude Codeに聞いた内容：「アップロードに失敗しました」

Claude Codeの回答：日本語のファイル名だと、Difyではアップロードに失敗することがある。同じ中身で英数字の名前のファイル（.md と .txt）を用意するので、順番に試してほしい。ファイルの文字コード（UTF-8）と大きさ（約6.6KB）には問題がないことも確認した。

実際に試したこと：
1. ファイル名を `ひだまり珈琲店_メニュー表.md` から `hidamari_menu.md` に変えてアップロードした
   - 結果：成功した

学んだこと：AIツールやWebサービスにファイルを上げるときは、ファイル名を英数字にするとトラブルが減る。

**遭遇したエラー②：手順にあるボタンが画面に見当たらなかった**

Claude Codeに聞いた内容：「ナレッジを押すと、『すぐに使えるナレッジベースを作成』、『カスタムナレッジベースを構築』、『外部ナレッジベースと連携』とあります。『ナレッジを作成』が見当たりません。」

Claude Codeの回答：Difyの画面が新しくなり、名前が変わっている。ファイルを上げるだけで作れる「すぐに使えるナレッジベースを作成」が、手順の「ナレッジを作成」にあたる。ほかの2つは、加工の流れを自分で組み立てる上級者向けと、外部の資料置き場とつなぐ方法。

実際に試したこと：
1. 「すぐに使えるナレッジベースを作成」を押した
   - 結果：ファイルのアップロード画面になり、先に進めた
2. 「検索テスト」の場所も分からなかったので聞いたところ、作ったナレッジの中に入ると左のメニューに出ると分かった
   - 結果：検索テストができた

学んだこと：Webサービスの画面は更新で名前や配置が変わる。見つからないときは、画面に出ている文字をそのまま伝えると、どれにあたるか教えてもらえる。

**遭遇したエラー③：LINEの「Webhook」をオンにできなかった**

Claude Codeに聞いた内容：「webhookはまだオンにできませんでした」

Claude Codeの回答：故障ではなく、この時点ではオンにできないのが正常。Webhookは「このURLに知らせて」という仕組みで、送り先のURLがまだ登録されていないため。プログラムを公開してURLを登録したあとにオンにする。

実際に試したこと：
1. Vercelにデプロイしてから、LINE DevelopersにWebhook URLを登録し、「検証」を押した
   - 結果：「成功」と表示され、「Webhookの利用」をオンにできた

学んだこと：仕組みが分かると、「できない」理由と正しい順番が分かる。

---

**気づいた問題④：プログラムのファイルが外から読める状態だった**

デプロイ後に確認したところ、`lib/handler.js` がブラウザから読める状態だった（合鍵は書いていないので危険ではない）。

実際に試したこと：
1. 手順書・メニュー表・テストは、Vercelにアップロードしない設定（`.vercelignore`）にした
2. `lib` フォルダを、Vercelが公開しない場所（`api/_lib`）に移した
   - 結果：プログラムのファイルは404（見えない）になり、`/api/webhook` だけが開いている状態になった

学んだこと：公開したあとは、「見えてほしいものだけが見えているか」を自分で確かめることが大事。

## D. 学習の振り返り

### 今回学んだこと

**技術的な学び：**
- **API連携の仕組み**：LINEとDifyは直接つながらない。間に中継プログラムを置き、「LINEから受け取る → Difyに聞く → LINEに返す」の流れを作る
- **Webhook**：「何か起きたらこのURLに知らせて」という仕組み。こちらから毎回確認しに行かなくても、LINEのほうから知らせてくれる
- **3つの合鍵の役割の違い**：
  - DifyのAPIキー：中継プログラムがDifyのボットを使うための鍵
  - LINEのチャネルシークレット：届いた通知が本物のLINEからかを確かめる合言葉
  - LINEのチャネルアクセストークン：中継プログラムがLINEに返信するときの通行証
- **環境変数**：合鍵はプログラムに書かず、サーバーの金庫（環境変数）に入れる。登録したら再デプロイしないと反映されない
- **ナレッジと知識検索（RAG）**：AIは資料を丸ごと読むのではなく、質問に近い部分（チャンク）だけを探して読む。探しやすい資料の作り方（1品＝1段落）が回答の質を左右する
- **問題の切り分け**：検索テストで正しいメニューが出ていれば、検索はできている。それでも答えがおかしければ、直すのは指示文のほう
- **デプロイ**：Vercelに置くと、パソコンの電源を切ってもボットが24時間動き続ける

**AIツールの使い方：**
- 画面に出ている文字やエラーメッセージを、そのまま伝えると解決が早い
- 「なぜ」を聞くと理解が深まる（Webhookをオンにできなかった理由など）
- 合鍵（APIキー）はAIにも見せず、自分の手で直接登録する。AIには「登録できた」とだけ伝えた
- 本物につなぐ前に、AIにテストを作ってもらうと安心して進められる

**開発の進め方：**
- 最初に全体の仕組みを図にしてから作り始めると、今どこの作業をしているかが分かりやすい
- 「Dify側 → APIキー → LINE側 → サーバー → つなぐ → 試す」と、1ステップずつ確認しながら進めた
- テストの質問（作り話をしないかを見る質問を含む）を先に決めておくと、うまくできたかを判断しやすい

### 作った機能からの発展アイデア

- **今回作った機能**：LINEで質問すると、ナレッジのメニュー表を調べてAIが答えるボット
- **発展アイデア**：
  - 「トーク画面の下にリッチメニュー（『メニュー』『営業時間』『アレルギー』のボタン）を作り、押すだけで質問できるようにする」
  - 「Difyの質問分類器で『予約』『クレーム』を見分け、その質問だけスタッフが手で返信するように引き継ぐ」
  - 「『よくある質問』『臨時休業のお知らせ』もナレッジに入れて、答えられる範囲を広げる」
  - 「料理の写真を送ると、どのメニューか答えてくれる画像対応」

### 次の課題に向けて

- Difyの「ログ」画面で実際の質問を見て、指示文やナレッジを改善する流れを試したい
- 質問分類器やIF/ELSEブロックを使って、質問の種類ごとに答え方を変えるチャットフローに挑戦したい
- エラーが起きたときに、Vercelのログを自分で読んで原因を探せるようになりたい
