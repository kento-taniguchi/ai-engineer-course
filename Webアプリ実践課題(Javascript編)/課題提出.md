## B. 実装内容

### 使用技術
- **言語**：TypeScript、JavaScript、SQL
- **フレームワーク**：React（Vite）、Tailwind CSS
- **データベース**：Supabase（PostgreSQL）
- **その他ツール**：bolt.new、Claude Code、GitHub、GitHub Actions、Vercel、LINE Messaging API、Google Cloud（ログイン用・Google Calendar API）

### 実装した機能
1. ToDo の登録・編集・完了・削除（期限切れは赤で表示、優先度順に並べる）
2. 日・週・月のカレンダー（1回クリックで予定を掴んで置き場所をクリック、ドラッグでも移動、ダブルクリックで編集、旗の欄から追加）
3. テンプレート・セット（コアのタスク＋前後のサブタスクをまとめて登録）
4. お客さんの名前の差し込み（例：「{お客さん} BASE-PLUS 対面パーソナル」）
5. 定期タスク（毎日・平日・毎週・隔週・毎月など）
6. 事業ごとの分類と、カレンダーの色分け
7. 単価と売上の集計（今日・今週・今月、事業ごと）
8. LINE 通知（毎朝7時に今日のタスク、毎晩22時に本日の売上、日曜は今週・月末は今月の売上）。メッセージの最後に、その画面を開くリンクを付けた
9. ログイン（Google、メールアドレスとパスワード、パスワードなしのメールログイン）
10. インターネットに公開して、スマホからも使えるようにした（スマホでは、画面下のボタンで一覧とカレンダーを切り替える）
11. **Google カレンダーの予定の取り込み**（読むだけで、Google 側の予定は変えない）
    - 何度取り込んでも同じ予定は二重に入らない。Google 側で変わった予定は直し、消えた予定は外す
12. **取り込んだ予定をセットで登録**：予定の名前に「目印の言葉」があれば、テンプレートのセット（細かい ToDo つき）で入れる。残りの部分をお客さんの名前にする
    - 例：目印「対面パーソナル」、予定「山岸さん 対面パーソナル」→「山岸さん BASE-PLUS 対面パーソナル」のセット
13. **Ctrl＋Z で元に戻す**（タスクの追加・変更・移動・完了・削除。セットの移動や取り込みは1回でまとめて戻る）
14. 一覧の上のボタンをアイコンだけにして、画面をすっきりさせた（Google の取り込みは Google のロゴ）

### 工夫したポイント
- 自分の仕事の流れ（セッション → お礼 → フィードバック）をそのままセットにして、1回で登録できるようにした
- Google カレンダーに入れた予約も、同じセットで入るようにした。アプリと Google の両方に二重で入力しなくてよい
- データは**ログインした自分だけ**が読み書きできるようにした（ほかの人がアドレスを知っても見られない）
- Google カレンダーの許可（通行証）は1時間だけ使えるようにし、ブラウザのタブの中だけに置いた（データベースや GitHub には保存しない）
- LINE 通知は GitHub Actions で動かすので、パソコンの電源が切れていても届く
- 鍵や合言葉は GitHub に載せず、Secrets（見えない保管場所）に入れた

## C. 実装過程

### 開発の流れ

#### 11月24日
**やったこと**：
- bolt.new の無料枠がなくなったので、ZIP でダウンロードして Claude Code で開発を続けることにした
- 期限、テンプレート、カレンダーの機能を追加してもらった

**遭遇した問題**：bolt.new が作ったデータベース（Supabase）が自分の一覧に出てこず、設定を変えられなかった

**実際に試したこと**：
1. 自分の Supabase プロジェクトを新しく作った
2. アプリの接続先（.env）を、自分のプロジェクトに切り替えた
3. 表を作る SQL を、Supabase の SQL Editor に貼り付けて実行した

**結果**：自分のデータベースで保存できるようになった

**学んだこと**：アプリとデータベースは別々で、接続先を変えれば別のデータベースを使える

#### 11月25日（機能追加）
**やったこと**：
- 機能を足すたびに、Claude Code が作った SQL を Supabase で実行した（セット・分類・定期タスク・色・単価の計5回）
- 1人ずつ作っていたお客さん別のテンプレート7件を、名前を差し込む1件にまとめてもらった
- 実際の画面を見ながら、使いにくいところ（旗の欄が狭い、カードが大きいなど）を伝えて直してもらった

**学んだこと**：データの入れ物（表）を増やすときは、先に SQL で列を足す必要がある

#### 11月25日（LINE 通知）
**やったこと**：
- 毎朝・毎晩の LINE 通知を作ってもらった
- GitHub に接続先を登録し、コミット・プッシュした
- 以前の Python の ToDo アプリから送っていた通知を止めた（朝に2通届かないようにするため）

**結果**：手動で試して、LINE に届くのを確認した

#### 11月25日（ログインと公開）
**やったこと**：
- ログイン機能を付けて、データを自分だけが使えるようにする SQL を実行した
- 通知用の合言葉を、自分でコマンドを打って GitHub の Secrets に登録した
- 手元のアプリでメールアドレスを登録し、自分を「持ち主」にした（公開する前に済ませた）

**遭遇した問題①**：SQL を実行するとき「Potential issues detected（RLS が無効な表がある）」という警告が出た
- **試したこと**：「Run and enable RLS」を選んだ
- **結果**：問題なく実行でき、ログインしていない人には0件しか見えないことを確認した

**遭遇した問題②**：合言葉を登録するコマンドが `syntax error near unexpected token '&'` で失敗した
- **原因**：PowerShell 用の書き方を、bash で動かしていた
- **試したこと**：bash 用の書き方に直したコマンドで、もう一度実行した
- **結果**：登録できた

**遭遇した問題③**：登録したパスワードを複雑にしすぎて覚えていなかった
- **試したこと**：ブラウザのパスワード保存、パスワードの決め直し、メールのリンクでのログインを付けてもらい、パスワードを変更した
- **結果**：スマホでもログインできるようになった

**公開の作業**：
1. Vercel に登録し、パソコンから `npx vercel login` でログインした（2段階認証のコードを入力）
2. 公開後、Supabase の「URL Configuration」に公開アドレスを登録した
3. スマホで公開アドレスを開いて、ログインできることを確認した

**Google ログインの設定**：
1. Google Cloud で同意画面を作り、自分をテストユーザーに追加した
2. ログイン用のクライアント ID を作り、戻り先（Supabase のアドレス）を登録した
3. クライアント ID とシークレットを Supabase に入れて、Google ログインをオンにした
4. アプリの画面から、今のアカウントに Google を追加した

**結果**：Google のボタンでログインできるようになった

**学んだこと**：ログインの仕組みは「サービス側（Google）で許可を作る → Supabase に入れる → アプリから呼ぶ」の3段階になっている

#### 11月26日（スマホ対応・LINE のリンク・ログインの整理）
**やったこと**：
- スマホでは一覧とカレンダーを並べると狭いので、画面下のボタンで切り替えるようにしてもらった
- LINE 通知の最後に「アプリで今日の予定を開く」などのリンクを付けた。LINE の中のブラウザだと Google ログインが使えないので、いつものブラウザ（Safari・Chrome）で開くようにした
- GitHub ログインと LINE ログインは使わないことにして、ボタンを外した（Google とメールアドレスで十分なため）

#### 11月26日（Google カレンダーの取り込み）
**やったこと**：
1. 予定を見分ける印の列（google_event_id など）を足す SQL を、Supabase で実行した
2. Google Cloud で「Google Calendar API」を有効にした（画面に「管理」と出ていれば有効）
3. Claude Code に、公開中のアプリを新しい版に入れ替えてもらった（`npx vercel --prod`）

**しくみ**：
- 「Google で許可する」を押す → Google の画面で「カレンダーの予定を表示」を許可する → 1時間使える通行証が届く → 予定を読んでタスクにする
- アプリの予定を Google に書き込むことはしない（読むだけ）

**学んだこと**：Google のデータを読むには、ログインの設定とは別に「API を有効にする」作業が必要

#### 11月26日（使いやすさの改善）
**やったこと**：実際に使って気になったところを伝えて、直してもらった
- 一覧の上の「テンプレート・セット」「定期」「管理」の文字をなくして、アイコンだけにした
- Google カレンダーの取り込みボタンを Google のロゴにした
- カレンダーで予定を選ぶと上に出ていた「〇〇を置く日時をクリック」の帯をなくした。かわりに、1回クリックで予定を掴むと、マウスの下に置き場所が点線で出るようにした。ダブルクリックで編集
- Ctrl＋Z で、間違えて動かした・消したタスクを元に戻せるようにした

**工夫**：Ctrl＋Z は、文字を入力している欄の中では、ふつうの「入力の取り消し」になるようにした

#### 11月26日（取り込んだ予定をセットにする）
**遭遇した問題**：アプリから入れた「BASE-PLUS 対面パーソナル」はセット（細かい ToDo つき）になるのに、Google カレンダーから取り込んだ対面パーソナルは1件だけで入り、細かい ToDo が入らなかった

**原因**：取り込みは、Google の予定をそのまま1件のタスクにしていて、テンプレートを使っていなかった

**試したこと**：
1. 取り込み画面に「セットで入れる予定」の欄を作り、セットごとに「目印の言葉」を決められるようにしてもらった
2. 予定の名前に目印の言葉があれば、アプリから登録したときと同じ作り方でセットにし、残りの部分をお客さんの名前として差し込むようにしてもらった
3. 前に1件だけで取り込んだ予定も、次の取り込みでセットに直るようにしてもらった
4. Google 側で時間が変わったら細かい ToDo も一緒に動き、予定が消えたら終わっていない細かい ToDo も一緒に外れるようにしてもらった

**結果**：Google カレンダーに予約を入れておけば、取り込むだけでセットが入るようにした

**学んだこと**：「外から来たデータ」と「アプリの決まり（テンプレート）」をつなぐには、見分けるための目印を決めておくとよい

## D. 学習の振り返り

### 今回学んだこと

**技術的な学び**：
- React の画面と、Supabase のデータベースを分けて作るしくみ
- RLS（行ごとに、誰が読めるかを決めるしくみ）で、データを自分だけのものにできる
- GitHub Actions を使うと、決まった時刻に自動でプログラムを動かせる
- Vercel を使うと、作ったアプリを無料でインターネットに公開できる
- Google の API は「許可（通行証）をもらう → その通行証でデータを読む」という流れで使う
- 「元に戻す」は、変える前の状態を覚えておき、逆の操作をすることで作れる

**AIツールの使い方**：
- 実際に使ってみて困ったことを、そのまま伝えると直してもらえる
- 「アプリから入れたものと、取り込んだものが違う」のように、比べて伝えると原因が早く分かる
- エラーが出たときは、画面の文字をそのまま貼ると早く解決する
- 秘密の値（パスワードや合鍵）は AI に見せず、自分で登録する

**開発の進め方**：
- 機能を足したら、すぐ画面で試して、気づいたことを次の依頼にする
- 公開する前に、ログインとデータの守りを先に用意する
- 手元（試運転用のアプリ）で試してから、公開中のアプリを入れ替える

### 作った機能からの発展アイデア
- **今回作った機能**：Google カレンダーの予定を読み、名前の目印でセットにして取り込む
- **発展アイデア**：「お客さんごとの売上と来店回数を出して、しばらく来ていないお客さんを LINE で知らせる」

### 次の課題に向けて
- Google カレンダーの取り込みを、毎朝自動で行えるようにしたい
- 月の売上目標を決めて、どのくらい届いているかを見られるようにしたい
- スマホでの表示を、実際に使いながらさらに見やすくする
