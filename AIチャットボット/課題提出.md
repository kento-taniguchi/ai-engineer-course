## B. 実装内容

### 使用技術
- 言語: TypeScript
- フレームワーク: React 18、Vite 7、Tailwind CSS 3
- データベース: Bolt Database（PostgreSQL ＋ Edge Functions。中身はSupabase）
- その他ツール:
  - bolt.new（アプリの大枠を作成）
  - Claude Code（ローカルへの引き継ぎ・不具合修正・動作確認）
  - Dify（チャットフロー＋ナレッジ検索のチャットボット）
  - Dify Chat API（/chat-messages、ストリーミングモード）
  - lucide-react（アイコン）

### 実装した機能
1. チャット画面：質問を送ると、Difyの回答がリアルタイムに少しずつ表示される
2. 回答の途中で止められる「停止」ボタン（途中までの回答も保存される）
3. 会話履歴サイドバー：過去の会話の一覧・切り替え・削除、新規チャット
4. 最初の質問から会話タイトルを自動でつける（40文字で省略）
5. Dify側の会話ID（conversation_id）を保存して、前の話を覚えたまま会話を続けられる
6. おすすめの質問ボタン（ウェルカム画面）
7. スマホ表示ではサイドバーをメニューボタンで開閉
8. エラー時は画面上部に原因を表示し、「×」で閉じられる

### 工夫したポイント
- DifyのAPIキーはブラウザ側に置かず、Edge Function（サーバー側の中継役）の Secrets で管理した（キーが盗まれて勝手に使われるのを防ぐ）
- 接続情報（.env）はGitに上げないよう .gitignore で除外した
- Difyのストリーミングは「回答のかけら（差分）」が届く仕組みなので、受け取ったかけらをつなげて全文にするよう修正した
- 会話IDは回答のかけら1つ1つにも入っているので、そこから拾うようにして、中継役を再デプロイしなくても会話の続きを覚えられるようにした
- Dify側でエラーが起きたとき、原因（エラーメッセージ）を画面に表示するようにした
- 停止ボタンを押したとき、途中までの回答が二重に保存されないよう処理を整理した

## C. 実装過程

### 開発の流れ

やったこと：
- bolt.newのプロジェクトをローカル（自分のパソコン）に引き継いだ
- コード全体を読んでもらい、改善点を洗い出した
- 不具合を修正し、Difyのひだまり珈琲店ボットと接続して動作確認した

遭遇したエラー①：作業フォルダが空で、引き継ぎができなかった
```
（フォルダにファイルが1つもない状態）
```
Claude Codeに聞いた内容：「bolt.newでWebアプリの大枠を作って、こっちに引き継ぎたいけど方法が分からない」

Claude Codeの回答：
- bolt.newの「Export」→「Download」でzipをダウンロードし、作業フォルダに展開すればよい
- GitHub経由で引き継ぐ方法もあるが、初回はzipが簡単
- 引き継いだ後は、bolt.newとローカルの両方で編集すると内容がずれるので、編集はどちらか一方にする

実際に試したこと：
1. bolt.newからzipをダウンロードして作業フォルダに展開した
   結果：ファイル一式と接続情報（.env）がそろい、`npm install` → `npm run build` が成功した

遭遇したエラー②：コード検査（lint）のエラー
```
supabase/functions/dify-chat/index.ts
  52:11  error  'supabase' is assigned a value but never used  @typescript-eslint/no-unused-vars
```
Claude Codeの回答：中継役（Edge Function）の中に、作ったけれど使っていない変数が残っている

実際に試したこと：
1. 使っていない変数と読み込み（import）を削除した
   結果：lintのエラーが0件になった

遭遇したエラー③：AIの回答が最後の一部しか表示されない（コードを読んで発見した不具合）
```
fullAnswer = evt.answer;  // 届いたかけらで毎回「上書き」していた
```
Claude Codeの回答：
- Difyの `message` イベントで届く answer は全文ではなく、回答を細かく分けた差分
- 上書きすると最後のかけらしか残らないので、つなげる（`fullAnswer += evt.answer`）必要がある
- bolt.newの引き継ぎメモには「累積全文」と書かれていたが、Difyの仕様と合っていない

実際に試したこと：
1. 差分をつなげる形に修正した
   結果：型チェック・lint・ビルドがすべて成功した
2. Edge Functionに直接テストの質問を送って中身を確認した
   結果：「申し」「訳」「ありません」のように細かく分かれて届いており、修正が必要だったことを実際のデータで確認できた

遭遇したエラー④：DifyのAPIキーが未設定
```
Dify API configuration is missing. Please set DIFY_API_URL and DIFY_API_KEY in edge function secrets.（503）
```
※ 引き継ぎメモとコードから、設定しないとこのエラーになることが分かっていた

実際に試したこと：
1. Difyでひだまり珈琲店アプリのAPIキー（app-で始まる）を発行し、bolt.newのデータベース管理画面（Secrets）に `DIFY_API_URL`（https://api.dify.ai/v1）と `DIFY_API_KEY` を登録した
   結果：Edge Function経由でDifyから回答が返ってくるようになった

遭遇したエラー⑤：テストで送った質問に、ボットが的外れな返事をした
```
Q: 営業時間を教えて
A: 申し訳ありません、ひだまり珈琲店に関するご質問にお答えしています。…
```
Claude Codeの回答：営業時間は指示文に書いてあるのに答えられないのは不自然。テストで送った日本語が、Windowsのコマンド上で文字化けしてDifyに届いていた可能性が高い

実際に試したこと：
1. 文字化けしない方法（Node.jsのプログラム）で送り直した
   結果：「営業時間は8:00から18:00まで…」と正しく回答した。アプリやDifyの問題ではなく、テストの送り方の問題だった

遭遇したエラー⑥：会話の続きを覚えられない
```
（届いたイベントの種類を調べると）events: message
→ 中継役が待っている「end」イベントが一度も届いていない
```
Claude Codeの回答：Difyのチャットフローが送ってくる「終わり」の合図は `end` ではなく `message_end`。そのため会話IDが保存されず、毎回新しい会話として扱われていた

実際に試したこと：
1. 回答のかけら（messageイベント）に入っている conversation_id を拾って保存するようアプリ側を修正した（中継役の再デプロイ不要）
   結果：型チェック・lint・ビルドが成功
2. 中継役も `message_end` を通すよう修正した（bolt.newで再デプロイすると反映）
3. 会話IDを引き継いで「さっきのドリンクはアイスもある？」と続けて質問した
   結果：前の回答を踏まえて答えられた

学んだこと：
- 引き継ぎメモ（AIが書いたものも含む）は正しいとは限らないので、公式ドキュメントや実際のデータで確かめることが大事
- ストリーミングは「全文が何度も届く」のか「差分が届く」のかで処理が変わる
- うまく動かないときは、原因がアプリなのかテスト方法なのかを切り分ける

## D. 学習の振り返り

### 今回学んだこと

技術的な学び：
- Edge Function（サーバー側の中継役）を使うと、APIキーをブラウザに見せずに外部APIを呼び出せる
- SSE（サーバーから少しずつデータが届く仕組み）の受け取り方と、Difyのイベントの種類（message / message_replace / message_end / error）
- Difyの conversation_id を渡すと、会話の続きとして扱われる
- Supabase（Bolt Database）のRLSで「誰が読み書きできるか」を決められる。今は誰でも読み書きできる設定なので、公開前にはログイン機能が必要

AIツールの使い方：
- エラーメッセージと一緒にコードを見せると解決が早い
- 「なぜ」を聞くと理解が深まる
- bolt.newで大枠を素早く作り、細かい修正や確認はClaude Codeで行う、という使い分けが便利
- AIが書いたコードや説明も、実際に動かして確かめる必要がある

開発の進め方：
- 引き継いだらまず「全体を読む → ビルドが通るか確認 → 改善点を洗い出す → 大事な順に直す」
- 1つ直すごとに型チェック・lint・ビルドを回して、壊れていないか確認する
- APIキーなどの秘密の情報はチャットやコードに書かず、管理画面に直接入力する

### 作った機能からの発展アイデア
今回作った機能：Difyのチャットボットを自作のWebアプリから使えるチャット画面

発展アイデア：
- 「ログイン機能をつけて、自分の会話だけが見られるようにする」（マルチユーザー化）
- 「回答のマークダウン（太字・箇条書き・表）をきれいに表示する」
- 「画像やファイルを送って質問できるようにする」（DifyのAPIはファイル添付に対応している）
- 「同じ画面で、別のDifyボット（BASE-PLUSの問い合わせボットなど）を切り替えて使えるようにする」

### 次の課題に向けて
- Webに公開する前に、ログイン機能とEdge Functionの利用制限を入れて、他人に使われてDifyの利用料がかかるのを防ぎたい
- 「メニューの中で一番安いドリンクは？」のような、全体を比べる質問にも答えられるよう、Difyのナレッジ検索の設定を見直したい
- bolt.newで中継役（Edge Function）を再デプロイして、ローカルの修正を反映させたい
