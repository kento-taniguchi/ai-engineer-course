# 公式LINEの自動返信・配信日の一斉送信

## 1. できること
| 動き | 内容 | 通数（無料プラン 月200通） |
|---|---|---|
| 自動返信 | 「セミナー」を含む文章（例：「セミナー参加」）に、配信日を迎えた最新回のYouTubeのURLを返信し、申込者として記録。初回・再開時は「次回からも送ります／停止は『配信停止』」と案内 | 使わない（返信は無料） |
| 停止 | 「配信停止」で一斉送信の対象から外す。ブロックされた場合も自動で外す | 使わない |
| 配信日の一斉送信 | 毎日19時台（日本時間）に、その日が配信日でURLのある回を、申込者全員に送る | 1人1通 |
| 手動の送信 | プチセミナーの回の画面の「今すぐ申込者に送る」 | 1人1通 |

- それ以外の文章には返信しない（公式アカウントのチャットで、これまで通り本人が対応できる）。
- 同じ回は二重に送らない（回ごとに送信の記録を残し、送信済み・送信中は送らない。500人ずつ再送キー付きで送るため、途中で再試行しても同じ人に二重に届かない）。
- 送る前に今月の残り通数を確認し、足りなければ送らない（画面に理由を表示）。
- 一斉送信の文面：その回の「公式LINEの配信予約」の下書き（URL入り）があればそれを使い、なければテンプレート。末尾に停止の方法を付ける。
- 返信で案内するのは「配信日を迎えた回」だけ。配信日前の回のURLは渡さない。

## 2. 確認の結果（2026-11-20）
| 確認したこと | 結果 |
|---|---|
| Webhookの検証（LINE Developers） | ✓ 成功 |
| 署名なし・偽の署名の通知、合言葉なしの配信、未ログインでの状況確認・送信は拒否 | ✓（すべて401） |
| 「セミナー参加」→ 自動返信が届き、申込者1人として記録 | ✓ |
| 「配信停止」→ 停止の返信、申込者0人（停止1）。再度「セミナー参加」で1人に戻る | ✓ |
| 手動の一斉送信（1人・1通） → 届く・送信済みの表示・ボタンが消える | ✓ |
| 配信日の自動送信（定期実行） | 未確認（次の配信日の19時台に確認） |

## 3. しくみ
```
お客さんのLINE ──「セミナー参加」──▶ 公式アカウント ──通知（署名付き）──▶ /api/line/webhook（Vercel）
                                                                       ├ 署名を確認
                                                                       ├ 申込者を記録（Supabase line_subscribers）
                                                                       └ 最新回のURLを返信（Reply API・無料）
Vercelの定期実行（毎日 10:00 UTC＝19時台 JST）──▶ /api/line/deliver（CRON_SECRET で確認）──▶ 申込者へ一斉送信（Multicast）
アプリの画面 ──「今すぐ申込者に送る」（ログイン中の本人）──▶ /api/line/deliver（POST）
```

| ファイル | 内容 |
|---|---|
| `src/app/api/line/webhook/route.ts` | LINEからの通知の受け口 |
| `src/app/api/line/deliver/route.ts` | 一斉送信（定期実行・手動） |
| `src/app/api/line/status/route.ts` | 連携状況（申込者の人数・通数・配信の記録。識別番号は返さない） |
| `src/server/line.ts` / `delivery.ts` / `supabaseAdmin.ts` | サーバー専用（秘密の鍵を使う） |
| `src/lib/lineLogic.ts` | 返信する回・送る回・文面・通数の判断（`npm run check` でテスト） |
| `src/components/LinePanel.tsx` | プチセミナーの回の画面の「公式LINE」欄 |
| `supabase/line.sql` | 申込者・配信の記録の表と、二重送信防止の関数 |
| `vercel.json` | 定期実行の設定 |

## 4. 秘密の鍵（Vercelの本番環境に登録。値はどこにも書かない）
| 名前 | 内容 | 取得元 |
|---|---|---|
| `LINE_CHANNEL_SECRET` | 通知の署名の確認（英数字32文字） | LINE Developers →「チャネル基本設定」 |
| `LINE_CHANNEL_ACCESS_TOKEN` | 返信・送信 | LINE Developers →「Messaging API設定」→ チャネルアクセストークン（長期） |
| `SUPABASE_SECRET_KEY` | サーバーからの記録の読み書き（アクセス制限を越えられる強い鍵） | Supabase →「API Keys」→ Secret keys（名前 `vercel_server`） |
| `CRON_SECRET` | 定期実行の合言葉 | ランダムに生成して登録済み |

- 鍵を変えたら、公開し直すまで反映されない。
- 鍵が漏れた・漏れた疑いがあるとき：LINEはトークンを再発行、Supabaseは `vercel_server` の鍵を削除して作り直し、Vercelに登録し直して公開し直す。
- 登録ミス（見出しの日本語を一緒にコピーした等）は、画面の「公式LINE」欄に「◯◯の形が正しくありません」と表示される（値は表示しない）。

## 5. 記録している個人に関わる情報
- 「セミナー」を含む文章を送ってきた人の、LINEの識別番号（userId）と、申込・最後の依頼・停止の日時だけ。名前・プロフィール・文章の内容は保存しない。ログにも出さない。
- 本人が送ってきたこと（自分からの申込）を記録の条件にし、初回の返信で配信と停止の方法を案内している。
- ブラウザからは申込者の一覧を読めない（人数だけを、許可した本人に表示）。
- 申込者の記録を消したいとき：Supabaseの SQL Editor で `delete from public.line_subscribers where …;`（全員なら条件なし）。

## 6. 運用の注意
- Supabaseの無料プランは1週間使わないと一時停止し、その間は自動返信も止まる（ダッシュボードで「Restore」）。
- 以前使っていた「セミナー参加」の自動応答メッセージは、二重に返信しないようオフにしてある（削除はしていない）。アプリの返信が動かないときは、これをオンに戻せばよい。
- Vercelの無料プランの定期実行は1日1回で、指定した時間帯（19時台）のどこかで動く。
- 月200通を超えそうなときは、送る前に止まる（画面に残り通数を表示）。
