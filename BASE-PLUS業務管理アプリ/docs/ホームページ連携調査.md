## 1. 確認できたこと（事実）

| 項目 | 確認結果 |

| `/api/availability` の内容 | 日付ごとに `営業（available）／休み（closed）` と、予約可能な時間枠の開始時刻の一覧（例：`["19:40","20:50"]`）。2026-07-29〜2026-11-30 の122日分。予約者名などの個人情報は含まれていない |
| 書き込みの可否 | このAPIで許可されている操作は **読み取りのみ（GET / HEAD / OPTIONS）**。外部から書き込むための公開された方法はない |
| 外部アプリからの読み取り | 他のサイト（このアプリなど）のブラウザから直接読む許可（CORS）は出ていない。サーバー側から読み取ることは技術的には可能 |

| Googleカレンダー | ホームページの公開部分には、Googleカレンダーの埋め込みや連携の痕跡は見当たらない（裏側は未確認） |

- このアプリ：16:10〜17:10 / 17:20〜18:20 / 18:30〜19:30 / 19:40〜20:40 / 20:50〜21:50 の **5枠・各60分（間10分）**

## 申込フォームについて（第4版で再確認・結論を修正）

**前回（第3版）の「予約は予約フォームではなく、InstagramのDMで受け付けている」という結論は、公開ページの文言だけから判断したもので、実際の運用（新規顧客は申込フォームで受付）と異なっていました。この結論は取り消します。**

### 再確認した範囲（読み取りのみ）
- トップページ、`/plans/personal`・`/plans/online`・`/plans/group`・`/insole` の各ページ
- それらのページで読み込まれるJavaScriptファイル（6本）
- よく使われる申込ページのURL（`/contact`・`/apply`・`/form`・`/entry`・`/trial`）の有無

### 確認できたこと
- 上記の公開ページ・JavaScriptの中に、**申込フォーム（Googleフォーム等の外部フォームを含む）へのリンクや送信先は見つからなかった**。
- 「体験・相談を申し込む」ボタンはトップページ内の `#contact`（相談の案内）へ移動し、その案内文・各プランページの文言はInstagramのDMを案内している。外部リンクは Instagram（プロフィール・DM）とインソールのメーカー情報のみ。
- `/contact` などのURLはいずれもページなし（404）。

### 確認できていないこと
- **申込フォームの場所（URL）と、ホームページからフォームまでの導線**
  - 推測はしていません。例えば、DMやLINEでフォームのURLを送っている、別のサービスのページにある、ログインが必要な場所にある、などの可能性がありますが、いずれも未確認です。
- フォームの設定内容（質問項目、回答の保存先、通知の送り先、自動返信の有無）
- フォームの回答と予約枠（ホームページの○×）・Googleカレンダーの関係

### 確認に必要な情報
1. 申込フォームのURL（または、フォームを作ったサービス名：Googleフォーム／その他）
2. 新規の方がフォームにたどり着くまでの流れ（ホームページのどこから／DMやLINEで送っている等）
3. フォームの質問項目と、回答の保存先・通知先（スプレッドシート、メールなど）
4. 申込後の流れ（日程調整・確定・事前ヒアリングシートの送り方）
5. ホームページの案内文（DMを案内している部分）を今後フォームの案内に変える予定があるか
- ※ 申込フォーム・事前ヒアリングシートの自動送信は、引き続き将来機能として扱います。公開中のホームページやフォームには変更を加えていません。

## 3. 連携の進め方の選択肢

### A. 既存のホームページを活用する
- 例：ホームページの「空き状況データ」を、この業務管理アプリ（またはGoogleカレンダー）から作られるデータに置き換える
- メリット：見た目・URL・SEO・現在の導線をそのまま使える。作り直しの手間が小さい
- 課題：
  - サイト機能のコードやデータの置き場所を編集できる必要がある（現状は未確認）
  - 外部から書き込む安全な方法（認証）が必要。書き込み用の窓口を作る場合、なりすまし防止の鍵が必要
  - 申込フォームと空き枠が連動していない場合、「表示上は空き」でも同時に2人から申し込みが来る可能性が残る（手動で調整）

### B. 予約部分を作り直す（予約機能を業務管理アプリ側に持つ）
- 例：業務管理アプリをクラウドで公開し、予約受付ページ・予約データ・Googleカレンダー連携を一体で作る。ホームページからはリンクや埋め込みで案内
- メリット：Googleカレンダーの他の予定・移動時間を含めた空き判定、**申し込みの同時発生を防ぐ仕組み（先着の確保・仮押さえ）**を一か所で実装できる
- 課題：ログイン・データベース・個人情報の保護・通知など、作る量が増える。運用費（サーバー・データベース）がかかる場合がある

### 重複防止（どちらの場合も必要）
1. Googleカレンダーの予定（BASE-PLUS以外も含む）と **移動時間** を前後に足した時間帯は「予約不可」にする
2. 申し込みの確定は1か所（データベース）で、**同じ枠に同時に確定できない仕組み**（先に確保した人だけ成功）にする
3. 確定したら、すぐにカレンダーとホームページの表示に反映する
4. 反映に失敗した場合は、業務管理アプリに「要確認」として表示する
