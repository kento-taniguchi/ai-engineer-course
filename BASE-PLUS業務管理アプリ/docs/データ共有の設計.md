### 自動同期のしくみ（`src/store/CloudSyncStore.tsx`、判断ルールは `decideAutoSync`）
- 変更から約2.5秒後に保存（続けて操作している間はまとめる）。画面を離れるときは未保存分をすぐ送る。
- アプリを開いたとき・画面に戻ったとき・1分ごと・ネットにつながったときに、クラウドを確認する。
- この端末に未保存の変更がなく、クラウドが新しい → 自動で読み込む。この端末だけ変更 → 保存。両方で変更 → 画面上部に「クラウドの内容を使う／この端末の内容を使う」を表示（上書きする場合は、上書き前のクラウドの内容をファイルに保存）。
- Googleカレンダーの控え・自動で作られた未着手のToDoは、どの端末でも作り直せるため「変更」とみなさない（2台を行き来しても競合にならないように）。
- まだクラウドとつないでいない端末（最初の選択をしていない端末）では何もしない。「クラウド保存」画面で一度だけ選ぶ。
- 「クラウド保存」画面で自動同期をオフにできる（オフのときは手動の「クラウドに保存」ボタン）。
| 写真・動画のアップロード | 未実装（保存場所とアクセス制御は設定済み） |
| 保存履歴（控え）からの読み込み | ✓ 控えを読み込むとその時点の内容に戻り、自動同期でクラウドとiPhoneにも反映。書き出したファイルから戻すと最新の状態に復帰することも確認 |

## 3. 構成

```
iPhone / PC のブラウザ
  └ アプリ（https で公開）
       ├ ログイン：Supabase Auth（Googleアカウント）
       ├ データ：app_state（1人1件の文書、版番号つき） … 保存は save_app_state 関数だけ
       ├ 控え：app_state_history（1時間に1回まで・最大500件）
       ├ 写真・動画：Storage の非公開バケット media/ユーザーID/… … 表示は期限付きURL
       └ Googleカレンダー：今の方式（ブラウザで接続）を継続
```

### 本人だけがログインできる仕組み
- Supabase の認証は **Googleログインのみ** を有効にし、メール・パスワードでの新規登録は無効にする。
- データベースの `allowed_users` に谷口さん本人のメールアドレスを1件だけ登録する。
- ほかの人がGoogleでログインできても、`is_allowed()` が false のため、**データベースが1件も返さない**（画面で隠すのではない）。

### データベースのアクセス制御（`supabase/schema.sql`）
- すべての表で行レベルセキュリティ（RLS）を有効化。未ログイン（anon）には権限を与えない。
- 読み取り：`owner = 自分` かつ `許可されたユーザー` のみ。
- 書き込み：直接の追加・変更・削除は禁止。`save_app_state` 関数だけが、本人確認と版番号の確認をしてから保存する。

### 上書き事故の防止（PCとiPhoneで同時に使った場合）
- 端末は「最後に読み込んだ版番号」を覚えておき、保存のときに送る。
- クラウドの版番号が違えば（別の端末が先に保存していれば）**保存しない**。画面に「他の端末で更新されています」と表示し、本人が「クラウドの内容を読み込む」か「この端末の内容で上書き（控えを残す）」を選ぶ。
- 判断のルールは `src/lib/cloudSync.ts`（自動テストあり）。

### 写真・動画
- 非公開のバケット `media`。保存場所は `ユーザーID/ファイルID.拡張子` で、本人のフォルダしか読み書きできない。
- 表示は数分間だけ有効なURL（署名付きURL）で行い、公開URLは作らない。
- 無料プランは1ファイル50MBまで。動画を保存する場合は、長さ・画質の上限を決めるか、有料プランで上限を上げる。

### バックアップと復元
| 種類 | 内容 |
|---|---|
| 自動の控え（アプリ） | 保存のたびに、直前のデータを1時間に1回まで控えに残す（最大500件）。画面から選んで戻せるようにする |
| Supabaseの自動バックアップ | Proプランで毎日（7日分）。無料プランにはない |
| 手動（今もある） | 設定画面の「データを書き出す（JSON）」。月に1回など、定期的にPCへ保存する |

### 接続エラー・保存失敗の表示（実装時の決まり）
- 保存に失敗したら、画面上部に「⚠ クラウドに保存できていません（この端末には保存済み）」を表示し続け、再試行ボタンを出す。成功するまで「保存済み」とは表示しない。
- 通信できない間もこの端末のブラウザには保存し、つながったら送る（送る前に版番号を確認）。
- ログインの期限切れ・許可されていないユーザー・競合・容量超過を区別して表示する（`CloudErrorKind`）。

## 4. 既存のブラウザ内データの移行（勝手にアップロードしない）

1. 移行の前に、設定画面の「データを書き出す（JSON）」でPCにバックアップを保存する。
2. 新しいアプリで本人がログインする。
3. クラウドが空の場合、アプリは**件数を表示して「アップロードしますか？」と確認**する（自動では送らない）。
   - 「（架空）」の付いていない選手・チームが含まれる場合は、「同意の取得とアクセス制御の確認が済んでいる」ことのチェックがないと送れないようにする。
4. 送信後にクラウドから読み戻し、件数が一致したことを確認してから「移行完了」と表示する。
5. 移行前のブラウザ内データは削除しない（`baseplus-backup-v◯` として残す）。
6. プチセミナーの画像・動画（IndexedDB）は、本人が選んだものだけを別にアップロードする。
7. iPhone側でログインし、同じ件数が表示されることを確認する。iPhone側に別のデータがあれば「どちらを使うか」を選ぶ画面が出る。

## 6. 進め方（あなたが画面で行う作業）

費用がかかる操作はありません（無料プランで試験）。各ステップを終えたら知らせてください。次の操作を案内します。

1. https://supabase.com でアカウントを作る（Googleアカウントで登録可。クレジットカード不要）
2. 新しいプロジェクトを作る（名前：`baseplus-test`、リージョン：Tokyo、データベースのパスワードは自動生成のまま。**パスワードはチャットに貼らない**）
3. SQL Editorで `supabase/schema.sql` を実行し、最後の1行で本人のメールアドレスを登録
4. Authentication → Providers で Google を有効にする（Google Cloud でもう1つ「ウェブ アプリケーション」のクライアントを作る。**このときのクライアントシークレットはSupabaseの画面にだけ貼る**）
5. Project Settings → API の「Project URL」と「publishable（anon）キー」を `.env.local` に書く（`service_role` / `secret` のキーは使わない）
6. ここまで終わったら、ログイン画面と保存処理（`SupabaseCloudStore`）を実装し、**架空データで**「本人は読める・別アカウントは読めない・競合時に上書きしない」を確認する
