## 2. 仮の仕様（要件で決まっていなかったため仮に決めたこと）

後から変更しやすいよう、主に `src/lib/todoEngine.ts` にまとめています。

### ToDoの表示タイミング
| ToDo | 表示開始 | 期限 |
|---|---|---|
| 前回記録を確認 | 指導前日の0:00 | 指導開始時刻 |
| リマインドを送る | 指導当日の0:00 | 当日12:00（指導開始が12時より前なら開始時刻） |
| フィードバックを作成／送る | 指導終了時刻 | 指導当日の23:59 |
| お礼を送る | 指導終了の1時間後 | 指導当日の23:59 |

- 強調表示（フィードバック作成・送信）：当日＝通常、翌日＝黄「翌日・未作成／未送信」、2日以上＝赤「◯日経過」
- その他のToDoは期限を過ぎると「期限切れ」（翌日は黄、2日以上は赤）
- 未完了のToDoは日付が変わっても消えず、「期限を過ぎた未完了」に残ります。
- レポートを保存すると「フィードバックを作成」は自動で完了。「フィードバックを送る」は自動では完了せず、ユーザーが「送信済みにする」を押します。

### 今日やること（選手・チーム単位のまとめ）— 改修2で追加
- 「今日やること」は対象者（選手・チーム）ごとに1行。行を押すと、その対象者のToDoが画面内で開閉します（開いた状態はタブを閉じるまで保持）。
- 緊急性（仮のルール、`src/lib/todayGroups.ts`）
  - 赤「期限超過」：指導の翌日以降も未完了のフィードバック作成・送信
  - 黄「要対応・今日中」：期限が今日までの未完了の業務（期限を過ぎていれば「期限超過」）
  - 通常：それ以外（例：明日の指導の事前確認だけ）
  - 対象者に複数ある場合は最も高いものを表示。完了・対象外は判定に含めない
- 開いたときは、表示中の指導に関係する完了・対象外の業務と、今日完了にした業務も確認できます。
- 対象者のない業務・プチセミナーなどは「その他の業務」。
- 「確認が必要」（予約の変更・削除など）は判断が必要なため、従来どおり別枠で上部に表示します。

### 重複防止
- 予約から作るToDoのIDは「予約ID:種類」で固定。何度同期しても同じToDoは1つだけです。
- 将来Googleカレンダーと同期する際は、予定のID（繰り返し予定は各回のID）を予約IDとして使う想定です。

### 予約の変更・キャンセル・削除
| 出来事 | 未着手 | 予定に入れた／作業中 | 完了・対象外 | レポート |
|---|---|---|---|---|
| 日時変更・延期 | 新しい日時に自動で追従 | 追従（作業時間を配置済みなら「確認が必要」） | リマインド・事前確認・お礼が完了済みなら「確認が必要」 | 残す |
| キャンセル | 自動で「対象外」（理由付き・元に戻せる） | 「確認が必要」 | そのまま | 残す |
| 削除（理由不明） | 「確認が必要」 | 「確認が必要」 | そのまま | 残す |
| 元に戻す | キャンセルで自動対象外にしたものを未着手へ | 確認表示を解除 | そのまま | 残す |

- 予約データ自体も「削除」状態として履歴を残し、物理的には消しません。
- 予定名から対象者を特定できない予約は「確認が必要」に表示し、ユーザーが選ぶまでToDoを作りません。

### プチセミナー

- 金曜配信 → 木曜日に「動画作成」「配信予約の準備」
- 「配信済み」にした回のToDoは表示しません。

### 売上
- 単価（架空）：対面パーソナル 6,000円 / オンライン 4,000円 / 体験 3,000円
- チームの月額契約は訪問回数に関係なく **1か月1件** で計上
- 状態：予定 / 実施確認 / 入金確認 / キャンセル / 振替。予定額はキャンセル・振替を除いて集計
- 予約をキャンセルすると、紐づく売上は自動で「キャンセル」。延期で月が変わると計上月も移動
- 契約内容を編集すると、未入金（予定）の月額に反映

### 写真・動画
- 試作版ではファイル本体を保存しません（ブラウザの保存容量は約5MBのため）。ダミー表示と、選んだファイルの名前・サイズのみ記録します。
- 各写真・動画（ホワイトボードを含む）は、指導記録（レポート）に紐づけられます。

### 音声入力・AI
- マイク・外部APIは使わず、サンプル文章とキーワードで項目に振り分けます。
- 当てはまらない項目は空欄のまま。どの項目にも当てはまらない文は「未振り分け」として表示し、勝手に備考などへ入れません。
- 振り分け結果は確認してから入力欄に反映（入力済みの項目には追記）。

### 発信・SNSのAI支援 — 改修2で追加
- テーマ候補の提案と投稿文の下書きはAIで支援する構想。伝えたいこと・台本・撮影カット・撮影・編集は本人が行い、AIによる自動作成はしません。
- **接続先は未確定**：要望にある「Muse」がどのサービスを指すか未確認のため、特定のサービスには接続していません。APIの有無・機能・料金・利用規約を確認してから `src/services/contentAssist.ts` の `ContentAssistProvider` を実装して差し替えます。
- 現在のデモ：テーマ候補は架空のサンプル。投稿文は「冒頭（テーマ）・動画の内容（本人入力をそのまま）・視聴者への一言・ハッシュタグ」をテンプレートで組み合わせるだけで、要約・生成はしません。
- SNSの段階は8つ（「撮影カット」を追加）。旧データの7段階は、台本の後ろに空の「撮影カット」を挿入して移行します（既存メモの位置は変わりません）。

### プチセミナーのサムネイル・動画 — 改修2で追加
- 保存先：ブラウザ内の **IndexedDB**（通常のデータ＝localStorageは約5MBのため、画像・動画は入りません）。
- サムネイル：長辺1280pxのJPEGに縮小して保存。動画：1本300MBまで（試作版の上限）。
- 保存後に読み戻してサイズが一致した場合だけ「保存済み（読み戻し確認済み）」と表示。容量不足・失敗時はエラーを表示し、保存したようには見せません。動画は「ファイル名だけ記録」も選べます（その場合は「動画本体は保存されていません」と表示）。
- 制約：このブラウザだけ／他の端末では見られない／サイトデータ削除や空き容量不足（特にiPhoneのSafari）で消えることがある／JSON書き出しに含まれない。
- **本番での提案**：クラウドのファイル保存（例：Supabase Storage、Firebase Storage、Google Drive）にアップロードし、アプリにはURLやIDだけを保存する。差し替えは `src/services/mediaStore.ts` で行います。

### 公式LINEの配信予約 — 改修2で追加
- 動画を登録した後に「公式LINEの配信予約へ進む」を表示。配信内容・配信予定日時・添付予定（メモ）を下書きとして保存できます。
- LINEには接続しておらず、自動送信・自動予約はしません。画面には常に「LINE未連携・予約未完了」と表示します。

### 今回の指導内容のメモ — 第3版で追加

### 動画の冒頭からサムネイル — 第3版で追加
- 登録済みの動画（ブラウザ内に保存済みのもの）から、0〜15秒の任意の時刻（0.1秒単位）の静止画を切り出し、長辺1280pxのJPEGで保存。
- 平均の明るさが低い場合は「黒い画面の可能性」と注意を表示。
- 作れない場合の表示：動画本体が未保存（ファイル名のみ）／このブラウザで再生できない形式（例：HEVC/H.265）／読み込みの時間切れ／映像がない／保存容量不足。
- すべてブラウザ内で処理し、外部へは送信しない。手動で画像を選ぶ方法も残している。

### 今日やることの分類 — 第4版で追加
- 分類：選手・チーム（予約から発生。対象者ごとの行）／発信・SNS／プチセミナー／その他の業務（対象者のない予約・手動の「その他」）。それぞれ開閉でき、未完了件数と最も高い緊急性を見出しに表示。
- 緊急性の色は第2版からのルールを維持：赤＝指導翌日以降の未完了フィードバック、黄＝期限が今日まで（「今日まで」）または期限を過ぎた業務（「期限超過（昨日まで）」等）。
- **対応日と期限は別**：対応日はその日から表示する日、期限は任意。期限がなければ「期限超過」にしない。期限を過ぎた未完了は翌日以降も表示し続ける。
- 「後日に変更」：同じToDoのまま表示日だけずらす（状態の履歴・関連情報は保持。期限は変えない）。

### 手動の仕事（臨時・繰り返し） — 第4版で追加
- 項目：名前（必須）、分類（SNS／プチセミナー／その他）、対応日（初期値は今日）、期限・所要時間・メモ（任意）、繰り返し（しない／毎週・曜日／毎月・日付。ない日付は月末）。
- 繰り返しは各回を「仕事ID:日付」のToDoとして作るため、同じ回は重複しない。今日までに来た回を作る（さかのぼりは最大35日）。
- 編集・削除の範囲：「今回のみ」（その回だけ変更／その回を作らない）・「今後の予定も含める」（設定を変え、この回以降の未完了の回に反映／この回以降を作らない）。完了した回の履歴は自動で消さない。
- 各回のToDoには作成時の名前・期限などを保存するので、設定を変えても過去の記録は変わらない。

### SNS・プチセミナーのToDo — 第4版で追加
- SNS：企画ごとに7つの作業（テーマ／参考動画の確認／台本と撮影カットの確認／撮影／編集／投稿文の確認／投稿）。対応日か期限を設定した作業だけToDoにする（勝手に日付を決めない）。ToDoから `/sns?reel=企画ID` の「作業の予定」へ移動。
- ToDoの完了と「投稿済み」は別。投稿済みは本人がSNS画面の「投稿済みにする」で記録（日時を保存）。
- プチセミナー：配信曜日ごとの「準備作業のルール」（作業名と配信の何日前か）から、配信回ごとにToDoを作る（ID：`seminar:回ID:task:作業`）。期限は配信日の前日まで。ルールから外した作業の未完了ToDoは表示しない（完了済みは残る）。
- 初期ルール（候補）：月曜配信 → 土曜日にテーマ・撮影・サムネイル確認／金曜配信 → 木曜日にテーマ・撮影・サムネイル確認・配信文確認・公式LINE配信予約。
- 第3版までの「動画を作成」「配信予約の準備」ToDoは、それぞれ「撮影」「公式LINE配信予約」の作業に引き継いだ（完了履歴を保持）。
- 「公式LINEの配信予約を設定する」は常に「LINE未連携」と表示。完了にしても配信予約・下書き・状態は変更しない。

### Googleカレンダー連携 — 第5版で追加
- 方式：Google Identity Services のトークン方式（ブラウザ内で完結）。設定値は OAuth クライアントID のみ（`.env.local` の `NEXT_PUBLIC_GOOGLE_CLIENT_ID`、または「Google連携」画面で入力）。クライアントシークレット・APIキーは使わない。
- アクセストークンはメモリ上のみ（保存・表示・ログ出力しない）。約1時間で失効、再読み込み時も再接続が必要。
- 権限（必要なときに求める）：読み取り＝`calendar.calendarlist.readonly`・`calendar.events.readonly`／書き込み（初回登録時）＝`calendar.events.owned`（自分が所有するカレンダーのみ）。
- 読み込み：選んだカレンダーの「2週間前〜60日後」。繰り返し予定は1回ずつ展開、削除された回も取得して変更を検知。日本時間（Asia/Tokyo）。終日予定は日付で扱う。
- 紐づけ：本人が対象者・種類を選んで確定（予定名の候補は表示のみ）。予約IDは「カレンダー＋予定ID」から決まるため、再読み込み・再紐づけでも予約・ToDoは重複しない。繰り返し予定は本人が選んだ場合だけ、ほかの回も自動で紐づける。「予約ではない」予定は非表示にできる。
- 変更の反映：日時変更 → 予約を更新して「確認が必要」にお知らせ（旧→新）。削除・キャンセル・期間内で見つからない → 予約を「削除扱い」にし、未完了ToDoは「確認が必要」（自動で対象外にしない）。レポート・指導メモ・完了履歴は消さない。Google連携の予約の日時はアプリでは変更せず、Googleカレンダーで変更する。
- 作業予定の登録：配置したToDoを、確認画面（予定名・日時・登録先・重なり）の後に登録。予定IDはToDoごとに固定（再試行・再登録で二重登録しない）。予定には `baseplusTodoId` を保存して紐づけ、配置の変更時は「カレンダーを更新」で反映、削除も可能。
- 失敗時：読み込み失敗・登録失敗・接続切れを画面に表示し、再試行できる。連携の履歴（最新20件）を保存。

### 第6版の準備（実用化に向けて）
- Googleカレンダー：紐づけ済みの予定が読み込み期間（2週間前〜60日後）の外へ移動された場合、一覧に出ないため「削除」と誤判定していた。期間内に見つからない紐づけ済みの予定は1件ずつGoogleに確認し、存在すれば「日時変更」として扱うよう修正（確認に失敗した場合は読み込み全体を失敗として何も変更しない）。
- **実際のGoogleアカウントでの確認（2026-11-19、PC・http://localhost:3000、試験用カレンダー「BASE-PLUSテスト」と架空の予定で実施）**：接続 → カレンダー選択 → 予定の読み込み → 架空の選手（伊藤 陽向）への紐づけ → 指導前のToDo表示（重複なし）→ ToDoの時間配置とGoogleカレンダーへの登録（1件のみ）→ 再読み込み・時間変更で重複しないこと → Google側の日時変更がアプリの「確認が必要」に旧→新で表示されること、をすべて確認。続けて、Google側での予定削除 → 予約が「削除扱い」・未完了ToDoが「確認が必要」に移ること、アプリから登録した作業予定をアプリから削除できることも確認。未確認：約1時間後の期限切れ表示（画面での明示的な確認）、iPhoneからの接続（https公開が必要）。
- 確認中に分かった改善（実装済み）：
  - キャンセル・削除扱いの予約は、「確認が必要」のカードと変更のお知らせに「この予約のToDoをまとめて対象外（◯件）」を表示。確認画面で対象のToDoを一覧し、Googleカレンダーに登録した作業予定も一緒に削除するかを選べる（初期値：削除する）。完了済みのToDo・レポート・指導メモは変更しない。有効な予約では動かない。
  - Googleカレンダーに登録済みの作業の「配置を解除」では、「Googleの予定も削除して解除」「アプリ内だけ解除」「やめる」を選ぶ確認画面を表示（以前は黙ってGoogle側の予定が残っていた）。Google側の削除に失敗した場合は配置を残し、理由を表示する。
- クラウド保存（試験版）：Supabase（試験用プロジェクト）にGoogleログインと手動の保存・読み込みを実装（`/cloud`）。保存は版番号つきで、他の端末が先に保存していれば上書きしない。アップロード後は読み戻して内容の一致を確認（データベースが項目の順番を並べ替えるため、順番に依存しない比較）。試験結果は `docs/データ共有の設計.md` の「0. 試験の結果」。
- https公開：Vercel（Hobbyプラン・個人の非商用利用）で公開。検索エンジンに載せない設定（robots: noindex）。iPhone（Safari）でログイン・クラウドからの読み込み・保存を確認し、PCとの間でデータが共有できることを架空データで確認（2026-11-19）。
- 自動同期：変更は約2.5秒後に自動保存、開いたとき・画面に戻ったとき・1分ごとに他の端末の変更を自動で読み込む。両方で変更があったときだけ画面上部で本人が選ぶ。PCとiPhoneで確認済み（2026-11-19）。詳細は `docs/データ共有の設計.md`。
- Google連携：接続の期限（約1時間。ブラウザだけで完結する方式のGoogleの決まり）が切れていても、「予定を読み込む」を押すとその操作の中で自動的につなぎ直す（「再接続」ボタンを別に押す必要はない）。期限なしで使うには、サーバー側でGoogleとつなぐ方式（秘密情報をサーバーで管理）への変更が必要。
- プチセミナーの動画（段階1）：動画ファイルはアプリに保存せず、YouTubeに **限定公開** でアップロードしたURLを登録する方式に変更。YouTubeアプリの共有URL（`?si=` 付き）・視聴ページ・ショート・ライブのURLを受け付け、追跡情報を除いた `https://youtu.be/ID` で保存（貼り付けると自動で登録）。登録すると、URL入りの公式LINEの配信文を1回の操作でコピーできる。公開設定（限定公開か）はアプリから確認できないため、YouTube側で確認する。ブラウザ内への動画保存は「任意」（動画の冒頭からサムネイルを作るときだけ）に変更。
  - 段階2（YouTubeへの自動アップロード）：YouTube Data API で可能だが、審査（監査）を通っていないアプリから上げた動画は非公開に固定されるため、審査が必要。未着手。
  - 段階3（公式LINE）：実装・確認済み（2026-11-20）。「セミナー」を含む文章への自動返信（無料）・申込者の記録・配信停止・配信日の自動一斉送信・手動送信。詳細は `docs/公式LINE連携.md`。
- PC・iPhone間の共有：設計（`docs/データ共有の設計.md`）、データベース設定（`supabase/schema.sql`）、判断ルール（`src/lib/cloudSync.ts`）、窓口（`src/services/cloudStore.ts`、現在は未設定で送信しない）を準備。設定画面に本番利用前の不足を表示。
