# BASE-PLUS 業務管理アプリ（試作版）

野球指導事業「BASE-PLUS」の毎日の仕事を、1つの画面から進めるためのWebアプリです。
アプリを開くと、その日にやるべきこと（ToDo）と予定が表示され、各ToDoから前回の記録・連絡文・レポート作成の画面へ進めます。

> **これは試作版です（実用化の途中）。**
> - データは**架空**です（実在の選手・チーム・個人情報は入れないでください）。
> - **Googleカレンダー**は実際に接続できます（Google側の初期設定が必要：[docs/Googleカレンダー連携の設定.md](docs/Googleカレンダー連携の設定.md)）。
> - LINE・Instagram・メール・音声認識・AIには**接続していません**。画面上では「デモ」「未連携」と表示しています。
> - 入力したデータは**今使っているブラウザの中だけ**に保存されます（試験中の「クラウド保存」画面でボタンを押した場合だけ、クラウドに保存します。架空データのみで試験中）。別のブラウザ・別の端末（パソコンとiPhoneなど）では共有されません（実用化の提案：[docs/実用化の提案.md](docs/実用化の提案.md)）。

## 1. 起動方法

### 必要なもの
- **Node.js**（バージョン 20 以上。動作確認は v26）
  - 確認方法：ターミナルで `node -v` を実行

### 初回だけ
```bash
cd "BASE-PLUS業務管理アプリ"
npm install
```

### 起動
```bash
npm run dev
```
ブラウザで **http://localhost:3000** を開きます。

止めるときは、ターミナルで `Ctrl + C` を押します。

### iPhoneで見るには
パソコンとiPhoneを同じWi-Fiにつなぎ、`npm run dev` を実行したときに表示される
`Network: http://192.168.x.x:3000` のアドレスを、iPhoneのSafariで開きます。
（iPhone側のデータはiPhoneのブラウザに別に保存されます）

### その他のコマンド
| コマンド | 内容 |
|---|---|
| `npm run build` | 本番用にビルド（エラーがないかの確認にも使えます） |
| `npm run start` | ビルドしたものを起動 |
| `npm run typecheck` | TypeScriptの型チェック |
| `npm run check` | ロジックの自動チェック（ToDoの重複防止・キャンセル時の扱い・データ移行・分類と緊急性・指導メモ・予約枠・参考リール・繰り返しの仕事・SNS／セミナーのToDo・Googleカレンダーの読み込みと紐づけ・データ共有の判断ルールなど144項目） |

## 2. デモの操作方法（おすすめの順番）

デモデータは「初めて開いた日」を基準に作られるので、いつ開いても下の流れを試せます。

### ① 今日の仕事を見る（ホーム）
- 「今日やること」は **選手・チーム／発信・SNS／プチセミナー／その他の業務** の4つに分かれ、それぞれ押すと開閉します。見出しに未完了件数と、緊急なもの（「期限超過」「今日まで」）が表示されます。仕事がない分類は「今日の仕事はありません」。
- 「選手・チーム」の中は、これまでどおり**選手・チームごとに1行**にまとまっています（例：山田 太郎　未完了 4件）。
- 名前の行を押すと、その人のToDoが開きます。もう一度押すと閉じます（「すべて開く／閉じる」もあります）。
- 行の色と文字で緊急性が分かります。
  - 赤「‼ 期限超過」：指導の翌日以降もフィードバックの作成・送信が終わっていない
  - 黄「! 今日まで」：期限が今日までの業務がある（期限を過ぎていれば「期限超過（昨日まで）」など）
- 期限を設定していない仕事は、対応日を過ぎても「期限超過」にはなりません（表示は続きます）。
- 開いたToDoの「後日に変更」で、同じToDoのまま表示する日をずらせます（履歴は残ります）。
- 開いた中の「完了・対象外にした業務」で、済んだ業務も確認できます。
- 「確認が必要」に、**予定名から対象者が分からない予約**が出ています。対象者を選ぶとToDoが作られます。

### ② 前回記録を確認し、今回の指導内容をメモする
- 「前回記録を確認」の **［前回記録を開く］** → 前回の内容・自主練習・最新の測定結果・写真（ダミー）が表示されます。
- **［確認した（完了にする）］** で完了します。
- 同じ画面の **［今回の指導内容をメモ →］**（または「今日やること」の「今回の指導内容をメモ」）から、今回の予定をメモします。
  - 項目：今回の目的・テーマ／大まかな指導内容／確認したいこと／準備する道具／自由メモ（すべて任意。短いメモだけでも保存可）
  - 画面上部に、紐づける **対象者と指導日時** が表示されます。
  - 前回記録の確認とは別の作業です（メモを保存しても前回記録の確認は完了になりません）。
- 指導当日は、選手・チーム画面の「今後の予約と指導メモ」や、月間予定の予定詳細から再確認できます。
- 予約の日時を変更・キャンセルしてもメモは消えません（日時が変わった場合はその旨を表示）。
- 伊藤 陽向さん（新規）の場合は「前回の記録がありません」と表示されます。

### ③ フィードバックを作成する（音声入力デモ）
- 山田 太郎さんの「フィードバックを作成」→ **［レポートを作成］**
- 「音声から下書きを作る」を開き、**［録音して文字起こし（デモ）］** → **［項目に振り分ける（デモ）］** → **［入力欄に反映］**
  - マイクは使わず、サンプル文章で動きを再現しています。
  - 当てはまらない項目（例：備考）は**空欄のまま**です。
- 内容を確認・修正して **［保存する］** → 選手詳細の「指導履歴・フィードバック」で確認できます。

### ④ 連絡を送る（リマインド・お礼・フィードバック）
- **［下書きを確認］** → 文章を編集 → **［文章をコピー］** または **［端末の共有機能］**（iPhoneなど対応端末のみ）
- 共有画面を開いただけでは「送信済み」になりません。実際に送ったあとに **［送信済みにする］** を押します。
- レポートが未作成の「フィードバックを送る」を開くと、作成画面へ案内されます。

### ⑤ ToDoの状態を変える
- 各ToDoの **［状態を変更］** から「未着手／予定に入れた／作業中／完了／対象外」を選べます。完了・対象外には理由を残せます。
- ページを再読み込みしても状態は保持されます。完了した仕事は「今日 完了・対象外にした仕事」で日時と理由を確認できます。

### ⑥ スケジュールに作業時間を入れる
- **パソコン**：ToDoカードを右側の「今日のスケジュール」へドラッグ＆ドロップ
- **iPhone**：ToDoの **［時間に配置］** → 開始時刻と所要時間を選ぶ
- 指導予定と重なると「⚠ 時間が重なっています」と表示されます（アプリ内だけに反映、Googleカレンダーには未連携）。

### ⑦ 予定の変更・キャンセル・削除を試す
「月間予定」で予定を選ぶと、次の操作ができます。

| 操作 | ToDoの扱い |
|---|---|
| 日時を変更・延期 | 未完了のToDoは新しい日時に合わせて表示。完了済みのリマインド等は「確認が必要」に表示 |
| キャンセル | 未着手のToDoは自動で「対象外」。作業中・配置済みのToDoは「確認が必要」 |
| 削除 | 理由が分からないため、未完了のToDoはすべて「確認が必要」 |
| 予定を元に戻す | キャンセルで自動的に対象外になったToDoを未着手に戻す |

どの場合も、**完了済みの記録や作成済みのレポートは削除されません。**

### ⑦-2 仕事を追加する（臨時・繰り返し）
- 「今日やること」の **［＋ 仕事を追加］**（または各分類の「＋ 追加」）から登録します。名前だけでも登録でき、対応日は今日になります。
- 入力できる項目：分類（SNS／プチセミナー／その他）、対応する日、期限・所要時間・メモ（任意）、繰り返し（しない／毎週・曜日／毎月・日付）。
- 繰り返しの仕事は該当する日に自動で表示され、各回の完了は別々に記録されます。
- 編集・削除はToDoの **［編集・削除］** か「登録した仕事・繰り返しの一覧」から。繰り返しは「今回のみ」「今後の予定も含める」を選べ、完了した回の履歴は消えません。削除前に対象を確認する画面が出ます。

### ⑧ 発信・SNS（テーマ選定・参考リールから台本と撮影カット・投稿文）
- 「作業の予定（今日やることに表示）」で、テーマ・参考動画の確認・台本と撮影カットの確認・撮影・編集・投稿文の確認・投稿の各作業に **対応日・期限** を設定すると、その日の「発信・SNS」に表示されます（日付は自動では決めません）。
- ToDoを完了しても投稿したことにはなりません。実際に投稿したら **［投稿済みにする］** を押します。
- 発信の対象（野球選手／保護者／指導者）を選び、**［テーマ候補を表示（デモ）］** → 候補から **［この企画のテーマにする］**。テーマは編集・保存でき、候補は「保存したテーマ」にストックできます。
- 「動画の内容」を自分で入力し、**［投稿文の下書きを作成（デモ）］** → 冒頭・内容・一言・ハッシュタグの下書きができます。編集・コピー・共有ができます（自動投稿はしません）。
- 「参考リールから台本・撮影カットを作る」：参考にしたいInstagramリールのURL（形式をチェック）、参考動画の内容メモ、伝えたい内容、長さの目安などを入れて **［台本・撮影カット・投稿文の下書きを作成（デモ）］**。
  - 出力：動画冒頭のフック／台本／撮影カット案（何を映すか・話す内容・順番・秒数）／投稿文。それぞれ編集・保存・コピーできます。
  - **URLだけでは参考動画の中身は読み取れません**（理由は画面に表示）。動画を見て内容や構成を自分で入力してください。参考動画の文章はそのまま使いません。
  - 医学・トレーニングの内容は自動で確認していません。「自分で確認した」にチェックするまで「未確認」と表示します。
- 撮影・編集は本人が行い、進捗とメモを記録できます。
- ※ テーマ候補は架空のサンプル、台本・投稿文はテンプレートです。AIや動画解析には接続していません。

### ⑨ プチセミナー（準備作業・サムネイル・動画・公式LINE）
- 「準備作業のルール」で、配信曜日ごとに作業と作業日（配信の何日前か）を設定します。初期値は「月曜配信分：土曜日に作業」「金曜配信分：木曜日に作業（配信予約の準備を含む）」の候補です。
- 作業日になると「今日やること」の「プチセミナー」に表示され、押すとその回の詳細画面が開きます。「公式LINEの配信予約を設定する」には「LINE未連携」と表示され、完了にしても予約済みにはなりません。
- 配信回の **［詳細・素材登録］** から、動画とサムネイル画像を登録できます。
- 動画を登録すると「動画の冒頭から作成」で、切り出す時刻（0〜15秒）を調整して静止画を切り出し、**［サムネイルに設定］** できます。冒頭が黒い画面のときは注意が出ます。ブラウザで再生できない形式などで作れないときは理由を表示します（画像を手動で選ぶこともできます）。
- 画像・動画は**このブラウザの中だけ**に保存されます。保存後に読み戻して確認できたときだけ「保存済み（読み戻し確認済み）」と表示します。容量不足などで保存できなければ、その旨を表示します。
- 動画を登録すると **［公式LINEの配信予約へ進む］** が押せるようになり、配信内容と日時を下書きできます。**LINEには接続していないので、予約は完了しません**（「LINE未連携・予約未完了」と表示）。

### ⑩ 時間を進めて確認する（設定画面）
「設定」→「デモ用の時刻」で時刻を進めると、「指導終了1時間後のお礼」や「翌日になったフィードバックの強調表示」をすぐに確認できます。

### ⑪ データを最初に戻す
「設定」→ **［デモデータを初期状態に戻す］**

## 4. フォルダ構成（どこに何があるか）

```
src/
├─ app/              … 各画面（URLごとのページ）
│   ├─ page.tsx      … 今日の仕事（ホーム）
│   ├─ players/      … 選手一覧・詳細
│   ├─ teams/        … チーム一覧・詳細
│   ├─ report/       … フィードバック・レポート作成
│   ├─ message/      … リマインド・お礼・フィードバック送信
│   └─ calendar/ sales/ sns/ seminar/ slots/ settings/
├─ components/       … 画面の部品（ToDoカード、スケジュール、グラフなど）
├─ lib/              … 画面に依存しない処理
│   ├─ types.ts      … データの形の定義
│   ├─ todoEngine.ts … 予約からToDoを作る・表示タイミング・強調表示のルール
│   ├─ todayGroups.ts … 「今日やること」を選手・チームごとにまとめ、緊急性を決めるルール
│   ├─ migrate.ts    … 保存データを新しい形へ移行（既存データを消さない）
│   ├─ slots.ts      … 予約枠の計算（通常枠・曜日・例外・予約との重なり）
│   ├─ operations.ts … データの変更（予約の延期・キャンセル、レポート保存など）
│   ├─ demoData.ts   … 架空のデモデータ
│   └─ time.ts       … 日本時間の日時処理
├─ services/         … 外部とつながる部分（今はすべてデモ実装）
│   ├─ calendar.ts      … Googleカレンダー連携の窓口
│   ├─ share.ts         … コピー・端末の共有機能
│   ├─ feedbackAssist.ts … 音声認識・AIによる振り分け
│   ├─ googleCalendar.ts … Googleカレンダーとの通信（接続・読み込み・作業予定の登録）
│   ├─ contentAssist.ts  … SNSのテーマ提案・投稿文（AI接続先は未確定）
│   ├─ mediaStore.ts     … 画像・動画の保存先（今はブラウザ内のIndexedDB）
│   └─ storage.ts       … データの保存先（今はブラウザ内）
└─ store/AppStore.tsx … アプリ全体のデータ管理と自動保存
```

外部サービスに接続するときは、主に `services/` のファイルを本物の実装に差し替えます。画面側のコードはほぼ変更不要になるよう分けてあります。

PCとiPhoneでデータを共有するための設計と試験結果は [docs/データ共有の設計.md](docs/データ共有の設計.md)、仕様の詳細・仮に決めたこと・今後の確認事項は [docs/仕様メモ.md](docs/仕様メモ.md)、ホームページとの連携調査は [docs/ホームページ連携調査.md](docs/ホームページ連携調査.md) にまとめています。

## 5. 技術構成
- **Next.js 16**（App Router）＋ **TypeScript** ＋ **React 19**
- グラフは外部ライブラリを使わず SVG で描画（依存を増やさないため）
- UIライブラリなし（`src/app/globals.css` に共通スタイル）
- 外部APIキーは不要（Googleカレンダーは「OAuth クライアントID」のみ。秘密情報は使わない）

## 6. Googleカレンダー連携（第5版）
- 左メニュー **「Google連携」** で、初期設定・接続・読み込むカレンダーの選択・予定の紐づけを行います。設定手順は [docs/Googleカレンダー連携の設定.md](docs/Googleカレンダー連携の設定.md)。
- 読み込んだ予定は「今日のスケジュール」「月間予定」に灰色で表示されます（終日予定・繰り返し予定にも対応）。
- BASE-PLUSの予約の予定は、対象者と日時を確認して **選手・チームに紐づけ** ます（予定名から候補を出しますが、自動では決めません）。紐づけた予約から、これまでと同じルールでToDoが作られます。何度読み込んでも重複しません。
- Googleカレンダーで日時が変わった・削除された場合は、次の読み込みで反映し、「確認が必要」に変更内容を表示します。レポートや完了の記録は消しません。
- ToDoを「時間に配置」するとき、**Googleカレンダーにも登録** を選べます（登録前に日時・登録先・重なりを確認。再試行しても二重登録されません）。
- 接続は約1時間で切れ、ページを再読み込みしたときも「Googleに再接続」が必要です（接続用の情報を保存しない安全な方式のため）。
- iPhoneから使うには、アプリを https で公開する必要があります（[docs/実用化の提案.md](docs/実用化の提案.md)）。
- 第4版までの架空の予約（デモ）はそのまま残り、Googleの予定とは別に表示されます。
